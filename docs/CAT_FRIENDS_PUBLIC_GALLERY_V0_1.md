# 猫咪咔咔｜猫友图鉴与猫卡公开规则 v0.1

> 状态：首版功能落地说明
>
> 更新时间：2026-09-09
>
> 页面名称：`猫友图鉴`
>
> 当前入口：`我的`页设置菜单，位于“使用记录”上方；暂不加入底部主导航

## 1. 功能目的

“猫友图鉴”用于浏览其他用户公开的猫生图。页面不要求登录，所有访问者都可以查看公开内容；猫主人可以在自己的猫卡详情中切换“公开 / 私密”。

点击猫卡进入公开猫档案详情，展示猫名、品种、标签、最新一次评分、手记、相遇时间和约百米级的公开位置；不打开对方的编辑、删除、放归、精确位置或原图信息。

## 2. 公共展示准入

只有同时满足以下条件的猫卡才进入“猫友图鉴”：

1. 对应 `cat_profiles.status === 'active'`；
2. 对应猫卡不是私密档案，即 `cat_profiles.visibility !== 'private'`；
3. 档案和相遇记录没有“放生 / 放归 / 删除”状态或时间标记；
4. 至少有一条有效相遇记录，且记录中的猫生图封面满足：
   - `media.coverStatus === 'ready'`；历史数据若缺少状态但存在有效封面 `fileID`，按 ready 兼容读取；
   - 存在 `media.coverFileID`，或 `media.posterResult.coverImage.fileID`，或 `posterResult.sourceImage.kind === 'cover'` 且有 `fileID`；
   - 云存储可以换取临时地址。

这里的封面是 `cover / poster-cover`，也就是图生图产生的无文字场景图。`original` 原图、`cutout` 透明主体图和 `poster` 完整海报都不能作为猫友图鉴的回退图片。

### 2.1 多次遇见同一只猫

- 以同一用户的 `ownerOpenId + catalogCatId` 归并为一张猫卡；
- 在该猫卡自己的相遇记录中，选择“最新一条满足封面准入的记录”；
- 不读取 `featuredRecordId` 作为公共图鉴主图；
- 因此最新相遇尚未生成猫生图时，仍可以展示之前已经完成的最新可用猫生图；如果从未有可用封面，则不展示。

## 3. 隐私字段

### `cat_profiles.visibility`

```json
{
  "visibility": "public"
}
```

允许值：

- `public`：公开展示在“猫友图鉴”，并可出现在个人主页和单猫公开分享；
- `private`：仅主人自己的猫卡可见，不进入公共图鉴、个人主页猫卡列表和单猫公开分享。

历史档案没有该字段时按 `public` 兼容。新建猫卡默认 `public`。

未绑定账号的本地猫卡只保存在本机，不会因为打开“猫友图鉴”而上传；本地切换的公开状态会在之后绑定并同步该猫卡时一并提交。

## 4. 接口与安全边界

### `cat-friends`

| action | 是否需要登录 | 作用 |
| --- | --- | --- |
| `list` | 否 | 返回所有公开且有可用猫生图的猫卡摘要 |
| `detail` | 否 | 按 `publicCatId` 返回一只公开猫卡的安全详情 |

列表接口不返回位置；详情接口只返回展示需要的字段、临时地址和四舍五入到约百米级的公开位置，不返回 `ownerOpenId`、原图 fileID、透明主体 fileID、精确位置、奖励明细或完整海报 fileID。`publicCatId` 是猫卡公开读取标识，不等同于用户身份。

### `sync-guest-data`

| action | 是否需要登录 | 作用 |
| --- | --- | --- |
| `set-cat-visibility` | 是 | 仅当前微信用户修改自己名下猫卡的公开状态 |

服务端根据当前调用上下文获取用户身份，不能使用客户端传入的用户 ID 修改他人的猫卡。

### 其他公共入口

- `profile-social` 读取个人主页时过滤 `visibility === 'private'` 的猫卡；
- `cat-archive-share` 创建和读取单猫公开分享时重新检查当前隐私状态，旧分享快照不能绕过私密设置；
- 海报生成和主人自己的猫卡详情仍可以读取自己的私密猫卡。

## 5. 页面交互

1. 底部主导航保留三栏：`相遇`、`猫卡`、`我的`；从“我的”页的“猫友图鉴”菜单进入猫友页面；
2. “猫友图鉴”页面展示两列猫生图卡片，图片区按 `359:537` 设置，图片使用 `mode="aspectFit"`，不拉伸、不裁切；
3. 点击卡片进入猫咪档案详情；详情评分取最新相遇记录，详情主图优先使用该记录的透明主体图；
4. 加载、空状态和云端失败状态分别展示；猫友图鉴每页展示 12 只，支持下拉刷新、上滑加载下一页，底部也提供“上一页 / 下一页”按钮按页浏览；
5. 猫卡详情底部增加“猫友图鉴”开关：
   - 开启：`猫友串门｜带着猫生图去和大家见面`；
   - 关闭：`猫友串门｜先在自己的档案里安静待着`；
6. 已登录用户的状态修改以服务端成功为准；未绑定用户只更新本地，之后随账号绑定同步。

## 6. 不做的事情

- 不展示没有猫生图的原图、抠图或默认透明小猫；
- 不允许访问者编辑、删除或修改他人的猫卡；
- 不向访问者提供他人的精确位置、原图或完整海报文件；
- 不将公共图鉴作为用户搜索、关注或评论系统；
- 不把个人主页的精选记录规则复制给猫友图鉴。

## 7. 验收清单

- 未登录打开“猫友”可以加载列表；
- 从“我的”页点击“猫友图鉴”可以打开列表，底部主导航不出现“猫友”；
- 猫友图鉴超过 12 只时显示“上一页 / 下一页”和当前页码；
- 猫友图鉴和猫卡列表均支持下拉刷新；上滑到列表底部会加载下一页，且不会突破每页 12 只的分页边界；
- 只有 `coverStatus=ready` 且能换取临时地址的猫卡出现；
- 已放生 / 放归 / 删除的猫卡不会出现在列表，也不能通过公开详情链接访问；
- 同一用户同一猫卡只出现一次，按最新可用猫生图排序；
- 原图、透明主体图和完整海报不会作为公共图鉴图片；
- 点击卡片无需登录即可打开安全的猫档案详情，并展示最新评分与手记；
- 公开档案详情可展示四舍五入后的约百米级位置，列表不展示位置；
- 主人切换私密后，公共图鉴、个人主页、旧单猫分享均不再展示该猫；
- 主人重新切换公开后，下一次列表刷新可重新出现；
- 绑定用户的隐私修改失败时，页面不会错误显示为已保存。

## 8. 猫生图成品复用

- 猫生图封面生成成功后，先写入对应 `encounters.media` 的封面字段，再继续 Canvas 海报排版。
- 同一猫卡相遇记录再次打开时，客户端和 `poster-cover` 云函数都会先查已有封面；命中后直接使用原 `fileID`，不重复消耗图生图调用。
- 完整海报 PNG 是另一份排版快照。它的临时地址失效或最终海报同步失败，不会删除已经保存的封面，也不会使公共图鉴重新生成。
- 公共图鉴的 `coverTempURL` 是按云端 `fileID` 临时换取的地址，过期后重新换地址属于正常读取，不是重新生成。

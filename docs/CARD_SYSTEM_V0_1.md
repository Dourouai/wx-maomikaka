# 猫咪咔咔 — 相遇卡基础规则与五级卡面样式 v0.2

> 当前阶段：卡片玩法与视觉结构设计稿
>
> 本文先定义卡片的生成规则、单面信息层级和五套视觉主题，不涉及代码实现。

五套样式的视觉对照见 [五级卡面样式对照板 V9](./CARD_STYLES_BOARD_V9.png)；V1–V8 保留作为早期版本。

Canvas 的五层拆分、统一坐标、图片裁切和开发交接规则见 [五级相遇卡 Canvas 分层与版式规则](./CARD_CANVAS_LAYOUT_V0_1.md)。

本版先落地**单面正面卡**：不制作反面，也不把卡片做成需要翻转的实体卡结构。名字、等级标签、四个数值、唯一编号和 50 字以内的相遇文案，都围绕同一张正面卡组织。猫咪名字最多 5 个字。

## 1. 卡片的定位

相遇卡是用户每次成功记录一只猫后获得的收藏结果。它参考集换式卡片的“编号、等级、属性、卡面”结构，但不做战斗、攻击、防御或卡牌对战。

卡片记录的是：**这一次在哪里、以什么状态遇见了这只猫。**

卡片等级来自本次相遇的 `咪咔`，不是猫咪本身的固定身价，也不代表猫咪有高低之分。

## 2. 卡片和编号的关系

一张成功的相遇卡包含三层身份：

```text
cardNo   = 这一次相遇卡的唯一编号
imageId  = 这一次使用的图片编号
catId    = 这只猫咪档案的稳定编号
```

规则：

- 每次识别成功并完成结算，生成 1 张新的相遇卡；
- 同一只猫再次被拍到，复用 `catId`，但生成新的 `imageId` 和 `cardNo`；
- 不是猫、图片不合格或服务异常，不生成相遇卡；
- `cardNo` 永不复用，卡片隐藏后编号仍然保留；
- 图鉴按 `catId` 聚合，卡片详情保留每一次相遇记录；
- 不预设固定猫咪总数，也不使用“还差多少张卡”的强制收集表达。

编号格式沿用 [图片与相遇卡编号规则](./ID_RULES_V0_1.md)，例如：

```text
No. MK-260902-000014
CAT-000378
```

## 3. 卡片生成流程

```text
按下快门并提交任务
  ↓
扣除 1 个罐罐
  ↓
识别出一只可收录的目标猫
  ↓
计算魅力 / 机灵 / 灵气
  ↓
计算咪咔并映射 C / U / R / SR / UR
  ↓
生成 cardNo，选择对应卡面主题
  ↓
保存相遇卡、猫咪档案和本次相遇记录
```

识别结果不是猫或不符合收录条件时，只结束本次拍摄，不生成卡片；服务异常时返还罐罐，也不生成卡片。

## 4. 卡片统一结构

五个等级使用同一套版式，避免像五个不同产品。卡片主视觉统一采用“猫咪 + 环境背景”的连续场景图；不同等级主要改变场景色调、卡框、徽章、标签层次、装饰符号和揭示动效。

### 4.1 正面信息层级

```text
┌────────────────────┐
│ SR · 惊鸿 CAT FOUND │  ① 等级标签：代码 + 中文名
│ No. MK-260903-...  │  ② 相遇卡唯一编号
│                    │
│    猫咪 + 背景场景图  │  ③ 主视觉，占卡面约 52%–58%
│                    │
│ 小橘        咪咔 84 │  ④ 名字 + 综合分
│ 魅力 80 · 机灵 83  │  ⑤ 三项数值摘要
│ 灵气 89             │
│ 相遇短笺           │  ⑥ 30–50 字文案区
│ ……                 │
│       CAT ARCHIVE   │  ⑦ 品牌签名
└────────────────────┘
```

正面必须保留：

- 猫咪与环境背景组成的场景图；
- 等级标签：等级代码 + 中文等级名，例如 `SR · 惊鸿`；
- 猫咪名字；
- 咪咔、魅力、机灵、灵气四个数值；
- 卡片唯一编号 `cardNo`；
- 一段 50 字以内的「相遇短笺」。

正面不放：

- 猫爪和咔咔分奖励数值；
- 用户的罐罐余额；
- 复杂模型说明；
- 精确 GPS 位置；
- 战斗属性、攻击力、防御力或价格感标签。

猫爪和咔咔分属于本次拍摄的结算奖励，在结果页单独展示，不让卡片看起来像兑换券。

场景图不是单独抠出的猫咪贴纸：猫咪要和街巷、窗台、店铺、屋顶或夜景形成空间关系，让用户收藏的是“这只猫出现在这个地方的瞬间”。背景可以适度虚化，但不能被纯色块完全替代。加入四个数值和短文案后，卡面采用参考卡的“大主图 + 叠放信息牌”结构，具体坐标以 Canvas 版式规则为准。

卡片信息区不使用统一的长进度条，而使用“猫咪名称纸签 + 咪咔分数徽章 + 三个属性数值标签 + 相遇短笺”的组合。不同等级可以改变纸签形状和徽章材质，让卡面有收藏卡的层次感；前台不展示 `100`、`/100`、百分比或满格进度条。

### 4.2 四个数值的展示规则

四个数值是卡面固定信息，不是战斗属性：

| 数值 | 卡面写法 | 视觉层级 |
| --- | --- | --- |
| 综合分 | `咪咔 84` | 最大、最醒目，使用圆章或主徽章 |
| 魅力 | `魅力 80` | 属性标签 |
| 机灵 | `机灵 83` | 属性标签 |
| 灵气 | `灵气 89` | 属性标签 |

- 卡面只展示实际结果，例如 `咪咔 84`、`魅力 80`；不展示分值上限；
- 四个分数的内部取值范围为 0–100，卡面只展示实际结果，不展示上限；
- 不使用 `/100`、百分比、长条进度、星级换算或战斗力词汇；
- 三项属性必须同时出现数值，不能只保留图标或只在详情页出现；
- 四个数值不重复计算：`咪咔`是三项属性的综合结果，魅力、机灵、灵气是构成项；
- 视觉上使用“1 个主徽章 + 3 个小标签”最稳妥，避免四个数字抢走猫咪主体。

### 4.2.1 三项属性图标

三个图标统一为「猫咪特征印章」系统，不使用通用的爱心、灯泡、普通闪光或单独猫爪：

| 属性 | 图标结构 | 识别含义 | 固定强调色 |
| --- | --- | --- | --- |
| 魅力 | 猫咪脸颊 + 胡须弧线 | 表情、亲和感、外观吸引力 | 柔珊瑚 |
| 机灵 | 竖耳猫眼 + 两条观察线 | 注意力、反应、动作感 | 雾蓝 |
| 灵气 | 弯曲猫尾 + 月光圆点 | 神态、气场、场景氛围 | 月光金 / 薄荷 |

图标执行规则：

- 使用同一套 24 × 24 网格、圆角线条和视觉重量；
- 图标在小尺寸下必须能独立识别，不依赖旁边的文字；
- 三个属性色固定，不随 C / U / R / SR / UR 等级色变化；
- `咪咔`使用主徽章，不再增加第四个属性图标，避免与三个构成项混淆。

评分占位规则：

- 评分计算中：主徽章显示 `咪咔 —`，三个属性标签分别显示 `魅力 —`、`机灵 —`、`灵气 —`；
- 评分待评估或证据不足：主徽章显示 `咪咔 待评估`，属性标签显示 `—`，不能用 `0` 伪装成有效分数；
- 服务异常、不是猫或拍摄失败：不生成卡片，不展示虚假的分数占位卡；
- 评分完成后，统一替换为实际整数，例如 `咪咔 84`、`魅力 80`，不出现 `100`、`/100` 或百分比。

### 4.3 名字与相遇文案

本版不制作反面。正面卡直接显示文案标题和 50 字以内的短笺，不再额外设计背面。

```text
名字：小橘
等级：SR · 惊鸿
卡号：No. MK-260903-000014

咪咔 84
魅力 80 · 机灵 83 · 灵气 89

相遇短笺
傍晚的绿门旁，它安静坐下。风吹过耳尖，它没有躲开，只看了你三次，最后轻轻眨眼。
```

- 名字是本张相遇卡的展示名称，可以由用户修改，但不能覆盖 `catId`；
- 名字最多 5 个字；输入框占位符使用「给猫咪取名」，未填写时卡面显示「未命名」；
- 超过 5 个字时不自动截断，输入框直接阻止继续输入并提示「最多 5 个字」；
- 文案标题固定使用「相遇短笺」，长度控制在 50 个中文字符以内，建议 30–50 字；
- 文案只描述照片中可见的猫咪、动作、光线和环境，不虚构精确位置、身份或心理事实；
- 文案直接放在正面信息区，保证收藏卡第一眼仍然以猫咪画面为主。

地点只展示城市或用户主动填写的模糊区域，不展示可反推出住址的精确坐标。

## 5. 五套卡面样式 V7

本稿按当前的 `C / U / R / SR / UR` 五档设计。如果基础档最终从 `C` 改为 `N`，只替换代码，不需要重做卡面主题。

下面的名称是视觉主题名；卡面中文等级名先使用当前工作标签，后续可只替换文字，不需要重做颜色和构图。

| 代码 | 中文等级标签（工作版） | 视觉主题名 | 主颜色 | 辅助颜色 | 卡面气质 |
| --- | --- | --- | --- | --- | --- |
| C | 街角 | 薄荷留影 | `#DCEAD8` 薄荷绿 | `#52745C` 苔藓绿 | 轻、干净、第一次记录 |
| U | 偶见 | 云朵探头 | `#E3DDF2` 云朵紫 | `#75668A` 灰紫 | 软、俏皮、有一点意外 |
| R | 稀遇 | 蜜糖闪现 | `#F7E2AD` 蜜糖黄 | `#A66E2C` 暖金棕 | 温暖、难得、带一点闪 |
| SR | 惊鸿 | 珊瑚星轨 | `#F5D4D4` 珊瑚粉 | `#B9544A` 猫爪珊瑚 | 明亮、心动、短暂高光 |
| UR | 神隐 | 月光神隐 | `#40304E` 夜幕紫 | `#F2C671` 月光金 + `#FF8F79` 珊瑚光 | 神秘、梦幻、最高辨识度 |

### 5.1 C｜薄荷留影

- 场景图：橘色猫坐在薄荷绿调的安静街巷里，保留石板路、植物和门窗等环境信息；
- 卡底：奶油白纸张，叠一块薄荷绿观察记录区；
- 边框：邮票齿孔边 + 单层苔藓绿细线，不使用发光；
- 装饰：四角取景线、两三个小圆点和一片小叶，像刚完成的一次观察记录；
- 场景图：保持真实原色，不加会改变猫咪毛色的滤镜；
- 信息牌：不规则纸质便签 + 叶片印章式咪咔徽章；
- 动效：卡片轻轻上浮，咪咔数字淡入；
- 适合表达：日常、自然、没有压力的第一次相遇。

### 5.2 U｜云朵探头

- 场景图：灰白猫从云朵紫调的窗台探出头，保留窗帘、植物和远处天空；
- 卡底：奶油白叠云朵紫软角块；
- 边框：双层圆角线 + 云朵形异形切口，模拟从卡片后面探头；
- 装饰：小叶、软胶贴纸和不对称圆点，不使用爱心作为主符号；
- 场景图：比 C 多一层柔和紫色外框，但不切断猫咪和窗台的空间关系；
- 信息牌：错位贴纸姓名牌 + 云朵角标 + 圆形咪咔徽章；
- 动效：边角贴纸微微弹一下，随后恢复；
- 适合表达：比日常多一点巧合和俏皮。

### 5.3 R｜蜜糖闪现

- 场景图：三花猫出现在蜜糖色店铺门口，保留遮阳棚、砖墙和街道光线；
- 卡底：暖奶油色，场景图下方使用淡蜜糖黄信息板；
- 边框：双层暖金压印边，局部叠加斜向卡纸层；
- 装饰：小纸箔、短闪光线和太阳切面章，不做满屏金色；
- 场景图：允许轻微暖色提亮，但不改变猫咪毛色和背景层次判断；
- 信息牌：斜向金箔带 + 金色圆形咪咔徽章，增加实体卡收藏感；
- 动效：揭示时出现一次短促的星光闪烁；
- 适合表达：难得遇见、画面里有一个特别瞬间。

### 5.4 SR｜珊瑚星轨

- 场景图：黑白猫走过珊瑚粉夕阳下的屋顶或楼梯平台，背景保留天空和城市轮廓；
- 卡底：奶油白 + 珊瑚粉分区，主标题使用猫爪珊瑚；
- 边框：柔和珊瑚双线，边缘加入一条不闭合的轨道弧线；
- 装饰：半透明轨道带、圆珠节点和短尾迹，不使用爱心图标；
- 场景图：外框可以使用珊瑚渐变，但不在猫咪和背景上叠加大量粒子；
- 信息牌：珊瑚色斜向丝带 + 珊瑚轨道咪咔徽章，形成动态构图；
- 动效：星轨绕卡片边缘走一小段后停止；
- 适合表达：一眼心动、转瞬即逝的高光相遇。

### 5.5 UR｜月光神隐

- 场景图：白橘猫停在夜幕紫的屋顶，保留月亮、远处城市和屋顶纹理；
- 卡底：夜幕紫卡框，内部仍保留奶油白信息区，避免整张卡过暗；
- 边框：月门拱形结构 + 月光金细边 + 珊瑚色小高光，形成柔和的深浅反差；
- 装饰：不完整月轮、少量星点和细小飞叶，不用皇冠或满屏金色；
- 场景图：只允许轻微月光晕染，猫咪真实细节和背景空间优先；
- 信息牌：深色姓名牌 + 月光金圆章，配合少量全息星点；
- 动效：揭示时月轮亮起，星点出现，再停留在静态卡面；
- 适合表达：非常少见的气质和不可复制的相遇感。

UR 不使用爆炸、火焰、皇冠或满屏金色。最高等级的特别感来自“安静、深色、留白和月光”，保持猫咪咔咔的温柔气质。

## 6. 等级颜色使用规则

等级颜色只服务于识别和收藏，不表达价格或战斗力：

- 猫咪与背景场景图永远优先，等级色只能出现在卡框、标签、分数和少量装饰上；
- 同一等级的卡片颜色保持稳定，猫咪和背景照片不能决定等级色；
- C / U 使用低饱和色，保证日常卡不会显得廉价或被“低级”羞辱；
- R / SR / UR 逐步增加高光，但每一级只增加一种主要视觉记号；
- 文本不能只靠颜色传达等级，始终同时展示代码和中文等级名，例如 `SR · 惊鸿`；
- 等级标签必须出现在正面卡上方或左上角的固定区域，不能只藏在详情页；
- 代码是稳定识别字段，中文名是用户理解字段，后续中文名调整不影响等级判定和编号；
- 深色 UR 卡必须保证正文、编号和按钮达到清晰对比度；
- 动效可关闭，静态卡面仍必须完整表达等级。

## 7. 卡片与结果页的分工

```text
结果页：告诉用户这次得到了什么
  ├─ 相遇卡
  ├─ 咪咔与等级
  ├─ 猫爪奖励
  ├─ 咔咔分奖励
  └─ 新勋章

图鉴卡：让用户回看遇见过谁
  ├─ 猫咪 + 背景场景图
  ├─ 名字与等级标签
  ├─ 咪咔、魅力、机灵、灵气
  ├─ 相遇短笺
  └─ cardNo
```

结果页可以让卡片先揭示，再从卡片下方出现 `猫爪 +115` 和 `咔咔分 +8`。保存到图鉴后的卡片不重复播放奖励动画。

## 8. 卡片交互

### 8.1 揭示

- C / U：轻微上浮和淡入；
- R：一次短星光；
- SR：一段短星轨；
- UR：月轮亮起后停住；
- 揭示完成后，等级标签先出现，再显示咪咔主徽章和三项属性数值；
- 四个数值只显示分数本身，例如 `咪咔 84`、`魅力 80`，不显示 `100`、`/100` 或百分比；
- 等级标签始终同时显示代码和中文名，例如 `SR · 惊鸿`；
- 所有等级的动效时长控制在 0.4–0.8 秒；
- 用户可以跳过动效，直接查看完整卡片。

### 8.2 打开卡面详情

- 点击卡片：展开同一张正面卡的信息区，不做正反面翻转；
- 详情态显示完整 `cardNo`、`catId`、四个数值、等级标签、相遇短笺和相遇时间；
- 不把模型置信度、内部错误码和图片文件编号放到第一层；
- 分享图优先导出正面，不默认附带用户罐罐余额或奖励余额。

### 8.3 同猫重复相遇

- 新卡进入同一 `catId` 档案的“相遇记录”；
- 图鉴主卡默认展示最佳照片或最近一次照片，由用户选择；
- 每张历史相遇卡保留自己的等级、咪咔、照片和 `cardNo`；
- 同一只猫不会因为重复拍摄自动升级，只有本次相遇重新计算分数。

## 9. 首版规则边界

首版先确定：

1. 一次识别成功 = 一张相遇卡；
2. 相遇卡使用统一版式 + 五套等级主题；
3. 卡片等级由咪咔映射，沿用 `C / U / R / SR / UR` 代码；
4. 猫咪与真实环境场景是主视觉，等级色不覆盖主体；
5. 卡片本身不承载猫爪、咔咔分等经济奖励；
6. 卡片唯一编号使用 `cardNo`，猫咪档案使用 `catId`；
7. 正面固定展示代码 + 中文等级名的等级标签；
8. 正面固定展示咪咔、魅力、机灵、灵气四个数值，但不展示 `100`、`/100` 或百分比；
9. 卡片采用单面设计，文案控制在 50 字以内，不制作反面。

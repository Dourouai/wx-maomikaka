# 猫咪咔咔 — 罐罐扣减规则 v0.1

> 当前阶段：玩法结算规则设计稿
>
> 本文只定义罐罐的扣减、返还和失败分流，不涉及代码实现。

## 1. 核心结论

罐罐代表一次“拍摄提交额度”，不是一次“识别成功奖励”。

**用户按下快门并成功提交拍摄任务后，立即扣除 1 个罐罐。**

后续即使识别结果不是猫、照片模糊或主体不符合收录条件，罐罐也不返还。只有能够确认是产品侧服务或系统异常，才返还这 1 个罐罐。

```text
快门前：不扣
  ↓
快门后，任务受理：立即扣 1 个
  ↓
识别未通过：已扣除，不发奖励
识别成功：已扣除，生成卡片并发奖励
服务异常：返还已扣除的 1 个
```

## 2. 每日额度

| 规则 | 定义 |
| --- | --- |
| 每日额度 | 每位用户每天 3 个罐罐 |
| 额度含义 | 1 个罐罐 = 1 次拍摄任务提交 |
| 相机页 | 打开和构图不扣罐罐 |
| 扣除时机 | 快门提交成功、服务端受理任务时 |
| 未使用额度 | 当天不累积到下一天 |
| 重置时间 | 每天 00:00，按 `Asia/Shanghai` 自然日计算 |
| 重复点击 | 同一拍摄只创建一个任务，只扣一次 |

## 3. 拍摄结果分流

| 场景 | 任务状态 | 罐罐 | 卡片与奖励 |
| --- | --- | --- | --- |
| 快门前取消、相机权限失败 | 未提交 | 不扣 | 不生成任务、卡片或奖励 |
| 识别结果不是猫 | `RECOGNITION_REJECTED` | 已扣除，不返还 | 不生成相遇卡，不发猫爪、咔咔分和勋章 |
| 图片模糊、猫太小、主体不符合收录条件 | `RECOGNITION_REJECTED` | 已扣除，不返还 | 不生成相遇卡，不发基础奖励和勋章 |
| 多只猫且无法确认目标 | `RECOGNITION_REJECTED` | 已扣除，不返还 | 不生成相遇卡，不发基础奖励和勋章 |
| 识别成功 | `COMPLETED` | 已扣除 | 生成相遇卡，计算咪咔，发猫爪、咔咔分并检查勋章 |
| 任务已受理后发生存储、模型或结算异常 | `SERVICE_REFUNDED` | 返还 1 个 | 不发奖励，允许重新拍摄 |
| 快门后退出页面、结果页未打开 | 继续查询原任务 | 按最终状态处理 | 不能因为用户没看到结果就自动返还 |

“识别失败”和“服务失败”是两类不同结果：前者说明这次拍摄已经完成但没有达到收录条件，后者说明产品没有能力完成这次处理。

## 4. 什么算产品侧异常

以下情况由服务端确认后，可以返还罐罐：

- 任务已受理并扣除后，图片存储、读取或处理服务不可用；
- 任务已受理并扣除后，内容安全服务或识别模型服务不可用、超时或内部报错；
- 结算服务异常，无法完成扣除后的最终处理；
- 其他由服务端记录并确认的系统故障。

如果服务端在扣除前就没有受理任务，直接视为“未提交”，净结果是不扣罐罐，不产生额外返还。

以下情况不自动返还：

- 识别结果不是猫；
- 图片质量不达标；
- 用户上传了不符合收录条件的主体；
- 用户在快门后主动退出、返回或关闭页面；
- 用户重复点击、重复提交或重复打开结果页。

如果请求是否到达服务端暂时无法确认，不立即判定为“失败返还”，而是使用 `captureId` 查询原任务状态，避免同一次拍摄既扣除又返还，或重复发放奖励。

## 5. 结算顺序

```text
检查今日剩余罐罐 > 0
  ↓
创建唯一 captureId
  ↓
服务端受理拍摄任务
  ↓
原子扣除 1 个罐罐
  ↓
上传、内容安全与猫咪识别
  ├─ 识别未通过 → RECOGNITION_REJECTED，结束，不返还
  ├─ 服务异常 → SERVICE_REFUNDED，返还 1 个，结束
  └─ 识别成功 → 生成 cardNo，计算咪咔，发放奖励，结束
```

每个 `captureId` 只能有一个最终额度结果：

```text
CAN_DEBIT       扣除 1 个罐罐
或
CAN_REFUND      返还 1 个罐罐
```

两者不能同时发生。识别未通过属于 `CAN_DEBIT`，不是 `CAN_REFUND`。

## 6. UI 文案

### 6.1 快门前

```text
会使用 1 个罐罐
```

### 6.2 识别不是猫或照片不合格

```text
这次没有遇见猫
罐罐已使用，本次没有获得奖励
```

按钮：`再拍一张`

### 6.3 服务异常

```text
服务出了点小状况
罐罐已返还，可以再试一次
```

按钮：`重新拍摄`

### 6.4 首页额度展示

无论识别成功还是识别未通过，只要任务已提交，首页都更新剩余罐罐；只有服务异常返还后，数量恢复。

```text
今日剩余罐罐 2 / 3
还可以拍 2 次
```

## 7. 与奖励的关系

- 识别成功：发放相遇卡、猫爪、咔咔分，并检查勋章条件；
- 识别未通过：只扣罐罐，不发相遇卡、猫爪、咔咔分和勋章；
- 服务异常：返还罐罐，不发相遇卡和奖励；
- 罐罐扣减不改变猫爪、咔咔分和咪咔的计算公式。

## 8. 首版验收口径

只要用户完成“按下快门并提交任务”，就应满足：

1. 该次拍摄最多扣除 1 个罐罐；
2. 不是猫或识别不合格时，罐罐保持已扣除；
3. 服务端确认产品异常时，最多返还 1 个罐罐；
4. 同一个 `captureId` 不重复扣罐、不重复返还、不重复发奖；
5. 结果页关闭或网络重试不改变最终结算结果。

## 一、可直接复制给模型的任务说明

请基于以下产品定义，为微信小程序「猫咪咔咔」生成一套完整的 UI 与交互方案。

产品定位：这是一个现实系猫咪记录与图鉴游戏。用户在现实生活中遇到猫咪，通过拍照记录这次相遇，系统识别猫咪的稳定生物特征和本次照片中的相遇表现，生成一张相遇卡，并把猫咪加入个人图鉴。

请重点设计以下页面和状态：

1. 首页 / 相遇页：显示今日剩余罐罐，并引导用户拍照；
2. 拍照页：相机取景、罐罐消耗、识别状态、权限和失败状态；
3. 结果揭示页：展示猫咪照片、等级、猫爪和咔咔分奖励；
4. 图鉴页：展示已发现的猫咪、筛选、重复相遇记录和未发现状态；
5. 我的页面：展示猫爪等级、相遇统计、最近记录和设置；
6. 状态机图：表现从首页到拍照、识别、结果揭示、写入图鉴的完整流程；
7. 元素图标：罐罐、猫爪、拍照、图鉴、我的、返回、位置、不打扰、心形对焦等。

请只围绕“记录与发现猫咪”设计，不加入对战、排行榜、商城、复杂任务、社交动态或固定猫咪总数。

视觉方向建议为「街角猫档案 / City Cat Archive」：温暖纸张底色、砖红重点色、档案编号、照片联系表、取景裁切线、记录卡和少量印章元素。真实猫照片是主角，插画只用于空状态、加载状态和装饰。

请输出：

- 页面结构；
- 页面之间的跳转关系；
- 每个页面的正常、处理中、成功、失败和空状态；
- 页面中的关键文案；
- 按钮和图标的作用；
- 不要输出生产代码，先输出设计稿级别的 UI 方案。

## 二、产品功能描述

### 1. 产品名称

中文名：**猫咪咔咔**

英文气质标签：**City Cat Archive / Street Cat Records**

### 2. 一句话功能

**每天用 3 个罐罐，拍下现实里遇见的猫，把一次偶遇记录成一张相遇卡，并逐步建立自己的猫咪图鉴。**

### 3. 核心循环

```text
打开首页
  ↓
查看今日剩余罐罐
  ↓
进入拍照页
  ↓
按下快门并提交任务，扣除 1 个罐罐
  ↓
识别猫咪与照片特征
  ├─ 不是猫 / 图片不合格：罐罐不返还，不发奖励
  ├─ 服务异常：返还罐罐
  └─ 识别成功：生成相遇卡与奖励
       ↓
    加入图鉴 / 增加相遇记录
  ↓
返回首页，更新剩余罐罐
```

### 4. 功能模块

#### 4.1 每日拍照额度

每位用户每天拥有 3 个罐罐。每个罐罐代表一次拍摄任务提交机会。首页和拍照页都需要让用户清楚看到剩余数量。

#### 4.2 猫咪识别

拍照后识别：

- 是否存在猫咪；
- 画面中有几只猫；
- 猫咪的品种或中性分类；
- 毛色、花纹、耳朵、脸部记号、尾巴、体态等稳定特征；
- 本次照片中的姿态、眼神、动作和场景关系；
- 识别置信度。

#### 4.3 猫咪档案

每只被确认的猫都有一个动态档案。系统保存稳定特征，用于判断之后是否可能再次遇到同一只猫。

不预设固定猫咪总数。图鉴显示“已发现 X 只”，不显示“X / 60”。

#### 4.4 相遇卡

每次有效拍摄生成一条相遇记录，包含：

- 用户拍摄的原始照片；
- 可选的风格化卡面图；
- 猫咪档案 ID；
- 本次拍摄时间和可选地点；
- 相遇卡唯一编号；
- 猫咪稳定特征；
- GLM 根据照片生成的有趣猫咪昵称（最多 5 个字符）；
- GLM 根据可见内容生成的猫咪描述（最多 50 个字符）；
- 本次相遇的魅力、机灵、灵气分数，以及咪咔；
- C / U / R / SR / UR 等级；
- 猫爪和咔咔分奖励；
- 一段简短、克制、不编造事实的卡片文案。

#### 4.5 图鉴

图鉴是用户查看所有猫咪档案和相遇记录的页面。

- 已发现猫咪：显示照片、名字、等级和最近相遇时间；
- 重复遇见：进入同一只猫的多次相遇记录；
- 未发现位置：使用“下一次相遇”或柔和占位，不显示固定总数；
- 支持按等级或状态筛选；
- 图鉴优先展示用户自己的真实记录。

#### 4.6 我的

我的页面是个人记录与成长入口，展示：

- 用户会员名称与猫咪漫游身份；
- 猫爪等级与成长进度；
- 已发现猫咪数量；
- 总相遇次数；
- 连续记录天数；
- 最近相遇；
- 相遇记录和基础设置。

会员名称、猫爪成长值和五级阈值见 [用户成长会员等级规则 v0.1](./MEMBER_LEVEL_RULES_V0_1.md)。

## 三、基础玩法规则

### 1. 罐罐规则

| 规则 | 描述 |
| --- | --- |
| 每日额度 | 每位用户每天 3 个罐罐 |
| 额度含义 | 1 个罐罐 = 1 次拍摄提交机会 |
| 进入拍照页 | 不消耗罐罐 |
| 点击快门 | 创建一次拍摄任务；任务受理后立即扣除 1 个罐罐；处理中禁止重复提交 |
| 识别未通过 | 罐罐不返还，不生成相遇卡，不发猫爪和咔咔分 |
| 服务异常 | 返还本次罐罐，不发奖励，允许重新拍摄 |
| 未使用额度 | 当天不累积到下一天 |
| 重置时间 | 每天 00:00，按 Asia/Shanghai 自然日计算 |
| 返回首页 | 立即刷新剩余罐罐 |

推荐的 UI 语义：

```text
今日剩余罐罐 3 / 3
● ● ●
还可以拍 3 次
```

### 2. 拍摄有效性

拍摄任务提交后进入识别流程；只有满足以下条件，才生成相遇卡并发放奖励：

- 照片可以正常读取；
- 内容安全检查通过；
- 至少识别到一只猫；
- 图片质量达到最低要求；
- 用户在多猫画面中明确选择一只目标猫，或画面只有一只猫。

首版建议：

- 不是猫：已提交任务，扣除罐罐，不发奖励，提示“这次没有遇见猫”；
- 图片过于模糊：已提交任务，扣除罐罐，不发奖励，提示重新拍摄；
- 多只猫：提示用户选择本次要记录的目标猫；
- 识别服务异常：属于产品侧异常，返还本次罐罐。

### 3. 扣除与返还

罐罐采用“提交即扣除、异常才返还”的机制：

```text
点击快门
  ↓
锁定并扣除 1 个罐罐，防止重复提交
  ↓
识别成功 → 生成相遇卡并发放奖励
识别未通过 → 已扣除，不发奖励
服务异常 → 返还罐罐
```

以下情况可以返还罐罐：

- 任务已受理后，服务端处理链路创建或执行失败；
- 图片存储或处理服务不可用；
- 内容安全或识别模型服务异常、超时；
- 服务端结算失败。

失败文案建议：

```text
这次没有遇见猫
罐罐已使用，本次没有获得奖励
```

服务异常文案建议：

```text
服务出了点小状况
罐罐已返还，可以再试一次
```

### 4. 每次拍摄的结果

一次有效单猫拍摄对应：

```text
1 个罐罐
1 张相遇卡
1 条相遇记录
1 次猫咪档案更新
1 次猫爪奖励
1 次咔咔分奖励
```

同一只猫再次被拍摄时，不创建完全重复的新猫咪档案，而是在原档案下增加新的相遇记录。

## 四、识别与生物特征规则

### 1. 模型分工

视觉模型负责从照片中提取事实：是否有猫、猫的数量、可见特征和置信度；当前版本同时根据可见内容生成受长度与事实边界约束的猫咪昵称和短描述。

HY3 后续负责将已确认的结构化识别结果扩展成更长的卡片文案、标签和故事。无论使用哪一个文本模型，都不能覆盖视觉模型的事实结果。

### 2. 建议保存的结构化字段

```text
catId
isCat
catCount
breedOrType
confidence
furColor
pattern
faceMarks
earFeatures
tailFeatures
bodyFeatures
stableTraits
capturePose
eyeContact
sceneRelation
glmCatFeatureProfile
glmFeatureVectorVersion
glmFeatureVectorDimension
```

### 3. 同一只猫的判断

当前 MVP 只把以下信息作为“可能同一只猫”的候选信号，不直接宣称唯一识别，也不自动合并档案：

- 花纹和毛色组合；
- 脸部记号；
- 耳朵和尾巴特征；
- 体态和体型；
- GLM 固定特征槽位编码出的临时向量相似度；
- 历史拍摄地点和时间，仅作为辅助，不作为唯一依据。

当前临时向量版本为 `glm-cat-vector.v0.1`，固定 83 维，仅在特征质量合格时生成。真正的视觉 embedding / re-identification 模型接入后，才进入候选检索、阈值校准和用户确认流程。

以下阈值仅作为未来真实 embedding 接入后的原型参数：

| 相似度 | 处理方式 |
| ---: | --- |
| ≥ 0.88 | 自动归入已有猫咪档案 |
| 0.75–0.87 | 标记为可能同一只，保留待确认状态 |
| < 0.75 | 创建新的猫咪档案 |

模型置信度不足时，宁可保留为“可能同一只”，不要强行合并。

## 五、评分与等级规则

### 1. 三项分数

三个分数均为 0–100，分数描述这次相遇卡的特别程度，不评价猫咪的生命价值，也不代表战斗力或价格。

| 分数 | 含义 | 权重 |
| --- | --- | ---: |
| 魅力值 charm | 照片中的表情、姿态和整体吸引力 | 1/3 |
| 机灵值 cleverness | 照片中呈现出的观察力、反应和聪明感 | 1/3 |
| 灵气值 aura | 神态、气质和辨识感 | 1/3 |

三项分数不评价猫咪本身的价值，也不使用图鉴品种稀有度加分。GLM 先返回可观察的 `scoreEvidence` 子项，服务端按固定权重计算最终 `scores`；详细子项、评分锚点和质量门槛见 [小猫评分与等级规则 v0.2](./CAT_SCORING_RULES_V0_2.md)。

### 2. 咪咔

```text
咪咔 = round((魅力值 + 机灵值 + 灵气值) / 3)
```

三项分数均为 0–100，咪咔结果四舍五入为整数，范围为 0–100。

### 3. 五级标签

代码先保留五档，中文等级名称和卡面短标签暂不写死：

| 代码 | 等级名 | 卡面短标签 | 分数区间 |
| --- | --- | --- | ---: |
| C / N | 待定 | 待定 | 0–49 |
| U | 待定 | 待定 | 50–64 |
| R | 待定 | 待定 | 65–79 |
| SR | 待定 | 待定 | 80–91，且至少 2 项分数 ≥ 70 |
| UR | 待定 | 待定 | 92–100，且灵气值 ≥ 85、机灵值 ≥ 80 |

等级是“这次相遇有多特别”，不是“这只猫有多高级”。

AR、SAR 等名称未来只可用于描述卡面插画或印刷工艺，不新增为第六级、第七级稀有度。

### 4. 等级分布

上线后需要用真实样本校准，首版目标分布可以参考：

```text
C    50%–60%
U    25%–30%
R    10%–15%
SR    3%–5%
UR    0.5%–1%
```

不要在每次拍摄时根据其他用户动态排名。阈值以版本参数统一调整。

## 六、奖励规则

### 1. 猫爪

**猫爪 = 用户经验值名称。**

建议计算：

```text
猫爪 = 70 + 咪咔 × 0.6
```

结果取最接近的 5 的倍数，约为 `猫爪 +70` 至 `猫爪 +130`。

例：咪咔为 75，获得 `猫爪 +115`。

### 2. 咔咔分

咔咔分按等级发放，先使用以下数值：

| 等级 | 咔咔分奖励 |
| --- | ---: |
| C | +3 |
| U | +5 |
| R | +8 |
| SR | +13 |
| UR | +21 |

咔咔分用于后续兑换、成就或其他轻量玩法；在兑换规则确定前，不要在 UI 中承诺具体商品或价值。

### 3. 结果卡展示

```text
✦ CAT FOUND ✦

橘色小家伙
R · [中文标签待定]

猫爪 +115     咔咔分 +8
```

奖励在结果卡中自动结算，不需要用户额外点击“领取”。

## 七、页面与交互描述

### 1. 首页 / 相遇页

页面任务：让用户知道今天还能拍几次，并立即进入拍照。

必须有：

- 今日剩余罐罐；
- 一个主要拍照入口；
- 简短、不打扰猫咪的提示；
- 底部导航：相遇 / 图鉴 / 我的。

正常状态文案：

```text
去遇见
一只猫

今日剩余罐罐 3 / 3
还可以拍 3 次

拍照
发现猫咪了吗？
```

额度用完文案：

```text
今天的相遇已经完成
明天再来遇见新的猫咪
```

首页不放：

- 固定总数；
- 猫爪和咔咔分明细；
- 排行榜；
- 多个并列主按钮；
- 复杂任务卡。

### 2. 拍照页

页面任务：帮助用户完成一次安静的猫咪拍摄。

必须有：

- 返回；
- 剩余罐罐；
- 取景框；
- 正在找猫状态；
- 不打扰模式 / 闪光关闭；
- 猫爪快门；
- 相册入口。

状态文案：

```text
正在找猫
它在这里 · 保持一点距离
会使用 1 个罐罐
```

识别中：

```text
正在看清它……
正在识别这只猫
```

### 3. 结果揭示页

页面任务：用很短的仪式感告诉用户“这次相遇已经被收下”。

顺序：

```text
照片
  ↓
CAT FOUND
  ↓
猫咪名字与等级
  ↓
猫爪与咔咔分奖励
  ↓
加入图鉴
```

不要展示复杂公式；可在详情页查看魅力、机灵和灵气分数，以及咪咔。

### 4. 图鉴页

页面任务：让用户回看遇见过的猫，并继续发现新的猫咪。

必须有：

- `我的图鉴` 标题；
- `已发现 X 只`；
- 全部 / 等级筛选；
- 猫咪照片卡；
- 猫咪名字、等级和相遇时间；
- 未发现位置的柔和占位；
- 重复相遇进入同一档案。

推荐文案：

```text
我的图鉴
每一次相遇，都会留在这里
下一次相遇
```

### 5. 我的页面

页面任务：展示用户自己的成长和记录，但保持轻量。

必须有：

- 用户会员名称与猫咪漫游身份；
- 猫爪等级；
- 成长进度；
- 已发现数量；
- 相遇次数；
- 连续记录；
- 最近相遇；
- 相遇记录入口。

推荐文案：

```text
城市漫游者
猫爪 Lv.03 · 成长值 1120
距离 Lv.04 · 猫巷探索家 还差 680 猫爪
最近的相遇
相遇记录
```

## 八、状态机描述

### 1. 主流程

```text
HOME_READY
首页可拍摄，剩余 1–3 个罐罐
        ↓ 点击拍照
CAMERA_READY
拍照页等待用户构图
        ↓ 点击快门
CAPTURE_LOCKED
锁定并扣除 1 个罐罐，防止重复提交
        ↓ 上传成功
HY3_SCAN
识别猫咪、生物特征和本次相遇表现
        ↓ 识别成功
REVEAL
展示相遇卡、等级、咪咔、猫爪和咔咔分
        ↓ 自动保存
ALBUM_SAVED
写入图鉴，增加相遇记录
        ↓
HOME_READY
返回首页，剩余罐罐更新
```

### 2. 分支状态

| 触发情况 | UI 状态 | 处理 |
| --- | --- | --- |
| 剩余 0 个罐罐 | `HOME_EMPTY` | 禁用拍照，提示明天再来 |
| 首次进入相机 | `CAMERA_PERMISSION` | 解释原因，引导去设置 |
| 图片质量不合格 | `PHOTO_REJECTED` | 罐罐不返还，不发奖励，提示重新拍 |
| 不是猫 | `NOT_A_CAT` | 罐罐不返还，不发奖励，提示寻找真实猫咪 |
| 多只猫 | `SELECT_TARGET` | 让用户选择一只目标猫 |
| 服务超时 / 失败 | `SERVICE_RETRY` | 返还罐罐，允许重试 |
| 重复点击快门 | `CAPTURE_LOCKED` | 保持 loading，不创建第二任务 |

### 3. 返回规则

- 从拍照页、快门前返回首页：没有提交任务，不消耗罐罐；
- 成功结果返回首页：额度减少 1，图鉴增加记录；
- 识别失败返回首页：额度已减少 1，不生成图鉴记录，保留失败提示；
- 服务异常返回首页：额度已返还，保留异常提示；
- 快门后退出页面：任务仍按已提交处理；重新打开时查询原任务状态，不能因结果页未打开而自动返还；
- 结果页可以进入图鉴查看刚刚生成的记录；
- 图鉴和我的页面不影响当天罐罐。

### 应该使用

```text
去遇见一只猫

轻轻按下，收下这次相遇
```

### 不要使用

```text
捕获目标
执行任务
战力
失败惩罚
稀有宠物
价值更高
剩余次数不足
集齐 60 只
进入藏品
```

### 语气

- 像一个温柔的城市观察者；
- 短句优先；
- 不夸大、不制造焦虑；
- 不把猫咪描述成战斗单位或商品；
- 识别不确定时使用中性表达，不编造品种、地点和故事。

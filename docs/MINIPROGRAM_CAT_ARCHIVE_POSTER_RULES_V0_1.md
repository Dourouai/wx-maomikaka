# 猫咪咔咔｜猫档案 Canvas 海报生成规则 v0.1

> 状态：v0.1 规则与首版页面、Canvas、`poster-cover` 封面链路已落地；当前实现模板为 `cat-archive-poster-v0.6`（9:16 竖版）。
>
> 本文定义“猫档案 → 海报生成 → 海报分享”的产品、数据和渲染规则；当前首版采用 9:16 竖版 Canvas，主图封面按 `359:537` 生成或回退。

## 0. 本文和参考图的关系

用户提供的猫档案截图只作为视觉参考，不是可执行指令，也不是海报数据来源。

本版采用以下视觉假设：

- 页面交互沿用截图里的「街角猫档案」语言：暖米白纸张、档案编号、细线分区、少量珊瑚色动作强调；
- 海报主体沿用上一轮确认的简约满幅照片方向：大图优先、底部信息区、内容先于装饰；
- 等级通过等级色外沿、内侧细描边和等级字母区分；五个等级共用同一套几何位置，只切换主题色和字母；
- 不使用旧稿的多重边框、浮雕、金属高光、大圆章、幽灵猫轮廓或把文字烘焙进图片的方式。

旧的相遇卡拆层文档仍用于理解历史素材，但本流程以本文的 9:16 海报几何和猫档案数据快照为准。本文不修改原有相遇卡规则。

## 1. 目标和一句话定义

用户在「猫档案」详情页点击“生成海报”图标，系统读取当前猫档案的展示数据和主图，生成一张固定比例的简约海报；用户可以保存图片或分享海报，接收者通过分享链路打开同一份公开猫档案。

核心原则：

1. **猫档案是唯一数据源**：海报不重新识别猫、不重新评分、不重新生成名字和文案。
2. **Canvas 是唯一文字排版器**：所有姓名、编号、等级、分数和文案由 Canvas 绘制。
3. **图片生成和海报绘制分开**：图片服务只返回“无文字的猫咪主图”，Canvas 再叠加文字和边框。
4. **预览和导出共用同一渲染器**：不能出现页面预览一套坐标、分享图片另一套坐标。
5. **公开分享使用快照**：分享的是用户主动生成时的档案快照，不暴露账号、精确位置、模型内部数据或云端文件 ID。
6. **生成图片使用独立展示编号**：每条生成图片/相遇记录分配一个 `archiveCode`，不再把 `catId` 的短序号直接印到海报上。

## 2. 首版范围

### 2.1 必须完成

- 猫档案详情页增加一个“生成海报”图标；
- 点击后进入独立的“海报生成中”加载页；
- 从猫档案读取主图、档案编号、名字、品种、短文案、等级和评分；
- 将猫图适配到固定海报比例；
- 使用 Canvas 2D 生成 PNG；
- 进入海报预览页；
- 支持保存到相册和分享海报；
- 分享卡的落地页仍然是公开猫档案，而不是依赖接收者本地文件的临时图片页。

### 2.2 首版不做

- 不做用户手动拖动猫、缩放猫或重新裁切的编辑器；
- 不做多张照片拼贴和海报背面；
- 不做为五个等级分别设计五套不同布局；
- 不让 AI 直接输出带文字、分数、边框或 Logo 的完整海报；
- 不把精确 GPS、用户头像、罐罐、猫爪、咔咔分、模型置信度和内部特征向量放到海报；
- 不因为点击生成海报而重新扣罐罐、重新识别或重新计算评分；
- 不在评分尚未完成时用 C 作为默认等级生成正式海报。

## 3. 页面与入口规则

### 3.1 页面职责

| 页面 | 职责 | 是否生成图片 |
| --- | --- | --- |
| `pages/card-detail/card-detail` | 展示猫档案；提供“生成海报”入口 | 否 |
| `pages/poster-loading/poster-loading` | 固定档案快照、准备图片、生成主图、绘制 Canvas | 是，后台生成 |
| `pages/poster-preview/poster-preview` | 展示最终 PNG；提供保存和分享 | 不重新生成 |

页面名称可以在实现时调整，但职责不能合并成一堆散落在详情页里的状态。

### 3.2 猫档案页入口

- 入口位置：猫档案详情页主图区域右下角，贴近当前主图但不压住猫咪主体；
- 图标语义：使用“图片/分享海报”图标，不使用删除、普通转发或相机快门图标；
- 图标旁的无障碍名称固定为 `生成海报`；小尺寸只显示图标，长按或辅助读屏必须能读出名称；
- 入口不依赖颜色表达，图标本身必须能辨认；
- 点击后立即锁定按钮，避免重复创建多个生成任务；
- 入口只检查档案是否可生成，不在点击时重新修改档案。

### 3.3 生成资格

允许生成的条件：

- 猫档案存在且至少有一条有效相遇记录；
- 有可读取的主图：优先主体图，其次安全校验后的原图；
- 有明确的猫档案展示名称；没有名称时使用 `未命名`，不阻断生成；
- 等级可以沿用档案中的正式等级快照；综合分或任一构成分缺失时，海报对应位置显示 `0`，不留空；
- 文案可以为空，但必须使用安全的默认短句，不能绘制空白占位框。

暂不允许生成的情况：

- 图片仍在上传、抠图或换取临时地址；
- 图片被安全检查拒绝、不是猫或包含多个无法确定目标的猫；
- 该档案已被放归、删除或公开分享快照已失效。

不能生成时，详情页显示“海报暂不可用”和具体原因；不跳入一个永远转圈的加载页。

## 4. 生成状态机

```text
idle
  → snapshotting       固定猫档案快照
  → preparing-image    获取主体图 / 原图
  → generating-image   可选：生成适配比例的无文字猫图
  → rendering-canvas   绘制固定边框、文字、图标和分数
  → validating         检查尺寸、文字和图片完整性
  → success            进入海报预览

任意处理中状态 → failed
failed → retry / use-original-image / back
```

### 4.1 加载页文案

加载页只展示当前阶段，不伪造精确百分比：

| 状态 | 主文案 | 辅助文案 |
| --- | --- | --- |
| `snapshotting` | 正在整理猫咪档案 | 保留这次相遇的名字和分数 |
| `preparing-image` | 正在准备猫咪照片 | 找到合适的画面比例 |
| `generating-image` | 正在调整海报画面 | 保留猫咪的样子，只整理构图 |
| `rendering-canvas` | 正在排版海报 | 把档案信息放回这次相遇里 |
| `validating` | 正在做最后检查 | 检查图片、文字和分数 |

要求：

- 使用不确定进度的轻量动画或状态点，不显示假的 `68%`；
- 生成页不可展示旧海报或上一只猫的图片；
- 允许用户返回，但返回后任务应标记为取消，不留下半张海报；
- 网络失败可重试；图片生成失败时优先提供“使用原图继续”，不要直接丢失整个流程；
- 连续点击、页面重复进入或系统恢复时使用同一个 `posterJobId`，不能产生多份互相覆盖的结果。

## 5. 海报数据来源和快照

### 5.1 数据源优先级

海报必须通过一个统一的 `buildPosterData()` 组装，不允许 WXML、Canvas 和分享回调各自拼字段。

```text
猫档案详情的标准化展示数据
  ├─ currentRecord：当前最新相遇记录的图片和评分
  ├─ featuredRecord：用户选定的档案主图记录（不用于海报）
  ├─ profile：猫档案名称、品种、特征和文案
  └─ share snapshot：需要公开的最小字段
```

字段来源规则：

| 海报字段 | 来源 | 规则 |
| --- | --- | --- |
| `sourceArchiveId` | `catId` / `catalogCatId` | 只做内部关联，不绘制到海报 |
| `sourceRecordId` | 当前最新记录的 `recordId` | 海报主图、封面和评分必须来自同一条最新相遇记录；精选记录只用于档案主图展示，不参与海报生成 |
| `archiveCode` | 生成图片/相遇记录的展示编号 | 固定为 `YYYYMMDD` + 6 位大写数字/字母，例如 `20240512XX11EE`；海报显示 `No. 20240512XX11EE` |
| `name` | `profile.name` → 最近记录名字 → `未命名` | 最多 8 个中文字符；超长先按规则缩短，不改变档案原值 |
| `breed` | `profile.breed` → 当前记录识别品种 | 只作为次要信息，可为空 |
| `traits` | `profile.traits` → 当前记录特征 | 最多 3 个，顺序固定，不按分数重排 |
| `copy` | `profile.posterCopy` → 当前记录海报文案 → 描述 | 最多 36 个中文字符，Canvas 固定占 2 行；短句也居中断行，超长按两行截断 |
| `levelCode` | 当前正式评分的 `levelCode` | 只允许 `C / U / R / SR / UR`；不能用默认 C 代替待评估 |
| `levelLabel` | 当前正式评分的中文等级名 | 海报可作为小号辅助信息，不能替代等级代码 |
| `mika` | 当前正式评分的 `overallScore` | 0–100 整数；评分未完成时不生成正式海报 |
| `charm` | `currentScoreItems[charm]` | 0–100 整数 |
| `cleverness` | `currentScoreItems[cleverness]` | 0–100 整数 |
| `aura` | `currentScoreItems[aura]` | 0–100 整数 |
| `photo` | 已验收封面图 → 安全原图 → 主体图 | 只接受已通过安全检查的素材；封面失败时明确回退 |
| `imageVersion` | 图片处理结果版本 | 保存用于复现，不绘制 |
| `templateVersion` | 当前海报实现模板版本 | 固定为 `cat-archive-poster-v0.6` |

### 5.2 推荐数据结构

```json
{
  "posterJobId": "poster_20260905_xxxxx",
    "templateVersion": "cat-archive-poster-v0.6",
  "sourceArchiveId": "cat_060",
  "sourceRecordId": "rec_xxxxx",
  "archiveCode": "20240512XX11EE",
  "levelCode": "R",
  "levelLabel": "稀遇",
  "name": "小虎斑",
  "breed": "狸花猫",
  "traits": ["安静", "警觉"],
  "copy": "午后的阳光刚刚好，遇见一只安静的猫。",
  "scores": {
    "mika": 78,
    "charm": 82,
    "cleverness": 72,
    "aura": 80
  },
  "sourceImage": {
    "fileID": "cloud://private/xxx",
    "kind": "cutout",
    "width": 1024,
    "height": 1536,
    "version": "cat-transform.v1"
  },
  "coverImage": {
    "fileID": "cloud://private/poster-cover-xxx",
    "status": "ready",
    "targetRatio": "359:537",
    "width": 718,
    "height": 1074,

  },

```

`coverImage` 为空或状态不是 `ready` 时，Canvas 使用安全原图或主体图回退；`posterImage.fileID` 保留为空，因为最终 PNG 仍由 Canvas 统一生成。

### 5.3 快照不可变规则

- 进入加载页后立即复制一份 `posterData`；后续用户改名、切换主图或档案同步，不影响本次任务；
- 预览、保存、分享全部使用同一份快照；
- 生成海报不会改写原图、主体图、评分和文案；封面生成成功或失败时只写入独立的 `cover*` 元数据；
- 海报完成后将去除本地临时路径的轻量 `posterResult` 写入对应 `encounters.media`；不新增海报集合，不把 Canvas PNG 当作数据库字段；
- `posterResult` 只记录模板、来源、封面引用、排版快照和生成时间，原始猫咪档案仍以 `cat_profiles` / `encounters` 的源字段为准；
- 首次封面生成成功后，以 `sourceArchiveId + sourceRecordId + templateVersion` 作为固定缓存身份；后续重复打开优先复用已保存的最终海报，不再调用 AI；
- 最终 PNG 的本地临时地址失效时，只使用已保存的 `coverFileID` 重绘 Canvas，仍不得再次调用 AI；
- 只有用户明确触发“重新生成”时，才创建新的 `posterJobId` 和新的渲染时间；普通重复进入沿用固定缓存身份；
- 海报构图规则升级时递增 `templateVersion` 与封面提示词版本，并清理旧的本地海报结果、旧 `poster-cover` 文件和记录中的 `cover*` 元数据；原图、主体图、档案、评分、等级和奖励数据必须保留；
- 本次 `cat-archive-poster-v0.6` 在 `MIKA` 与主分数层级基础上增加文案安全间距，文案最多 36 个字符并固定均衡为两行；只在模板缓存失效时重绘 Canvas，已生成的 `poster-cover` 仍按记录复用，不重复调用 AI；
- `archiveCode` 在生成图片/相遇记录首次落档时创建，格式为 `YYYYMMDD` + 6 位大写数字/字母；同一条记录重复打开、同步或分享时沿用原值；
- 同一设备生成新编号前检查本地已占用编号，发生随机碰撞时重新生成；编号不包含 `catId`、`recordId`、`shareId` 或用户身份；
- 旧记录没有编号时，按其记录 ID 建立一次稳定的本地兼容编号，不再显示旧的 `0027` 等猫卡短序号；
- 分享快照只保存用户可见字段，不能把完整本地记录直接上传。

## 6. 图片适配和比例生成规则

### 6.1 海报比例

- 标准海报比例固定为 `9:16`（宽:高）；
- Canvas 逻辑尺寸：`750 × 1334`；
- 导出建议尺寸：`1500 × 2668`，根据设备和微信限制可以降为同一比例的较小尺寸；
- 预览缩放只改变显示大小，不改变逻辑坐标和导出比例；
- 主图区域和整张海报不是同一个比例：主图区域为 `718 × 1074`，约占画布高度的 80%；底部白色信息区从 `y=1090` 开始，占 `228 px`；主图和信息区直接相接，不额外叠加卡框；
- 主图区域的目标比例约为 `359:537`（约 `0.67:1`），图片服务按这个区域比例适配；不能把 `9:16` 整张海报比例误传给主图服务；
- 主体图使用更小的内缩安全边距，让透明主体在长画幅中占更大比例；完整原图继续使用 `cover`，不拉伸猫咪。

### 6.2 主图来源优先级

```text
featuredRecord.coverFileID（coverStatus=ready）
  → featuredRecord.photoPath / originalFileID
  → featuredRecord.cutoutPhotoPath / cutoutFileID
  → 最新有效记录的安全原图 / 主体图
  → 没有图片：失败，不生成空海报
```

当前简约满幅照片风格优先使用安全校验后的原图；主体图和原图的处理方式：

- 有已验收封面图：直接按 `cover` 裁切进主图区域，不再次调用模型；
- 没有封面图：本地海报首次生成时调用独立 `poster-cover` 链路，使用原图生成无文字场景图；
- 只有完整原图：优先用 `cover` 裁切，锚点以猫脸和主体中心为依据；不得拉伸、压扁或把猫重新识别成另一只猫；
- 原图分辨率不足：允许轻微放大并提示“使用原图继续”，不凭空补造猫脸细节；
- 图片服务失败：回退到原图裁切；原图也不可用时才进入失败态。

### 6.3 猫咪封面生成服务

如果没有已验收封面图，调用单独的 `poster-cover` 服务，服务只负责图片区域，不负责整张海报。具体的猫咪保真与背景生成边界见 [猫咪图生图封面规则 v0.1](./CAT_IMAGE_TO_IMAGE_COVER_RULES_V0_1.md)。

输入：

- 经过安全检查的原图 `fileID`；旧记录没有原图 fileID 时才使用可靠主体图；
- 目标尺寸 `718×1074`、比例 `359:537`（主图区域），不是整张海报的 `9:16` 比例；
- 构图、风格和禁止文字等规则由服务端固定提示词控制，不把 `archiveCode`、分数或 `levelCode` 传给模型。

输出：

- 一张没有文字、编号、等级字母、分数、边框、Logo、水印和第二只猫的图片；
- 保持原猫的花色、脸部特征、耳朵、四肢和尾巴；
- 猫咪主体只占画面面积约 `8%–15%`、高度约 `22%–30%`，宽度不超过画面 `45%`；背景至少占约 `70%`，不得生成近距离大猫特写；
- 返回图片版本、尺寸、来源记录和请求 ID，并持久化 `coverFileID`；
- 失败时返回明确错误码，不返回一张看似成功但内容被重绘的图片。

硬性禁止：

- 让文生图模型直接生成完整海报；
- 让模型在图片里写中文、英文、分数或档案编号；
- 用一张新的 AI 猫替换原档案中的猫；
- 把等级色扩散到猫咪毛发或环境主体上；
- 生成多猫、人物、额外水印、店铺广告或无法解释的文字。

## 7. Canvas 分层和合成顺序

### 7.1 五层结构

```text
L0 数据快照       posterData、素材版本、渲染版本，不直接绘制
L1 海报底层       按等级换色的外沿、白色信息区底色、单圈固定描边
L2 主图层         无文字猫咪主图，按主图区域裁切或填充
L3 固定元素层     等级字母、右上编号位置和三组指标图标
L4 动态信息层     名字、两行文案、MIKA、三组指标文字和数值
```

规则：

- L1–L3 为模板和固定组件；L4 由 Canvas 根据快照绘制；
- 动态文字、数字和图标不能烘焙到 L2 图片里；
- 图标优先使用 SVG 或 Canvas Path，保持线宽和尺寸一致；
- 不在一个位图里同时包含底色、边框、文字和分数，否则后续无法修复溢色和对齐；
- 所有层使用同一套 `templateVersion` 和 `levelCode`，禁止混用旧版固定元素。

### 7.2 建议版式

```text
┌──────────────────────────┐
│ C                    No. │  ← 等级色外沿、等级字母、右上白色编号
│                          │
│                          │
│       猫咪主图           │  ← 约 75%，无文字图片
│                          │
├──────────────────────────┤  ← 一条清晰的照片 / 信息区边界
│ 猫名                 MIKA│
│ 相遇短文案               │  ← 固定两行
│ 相遇短文案               │
│  ◇ 魅力 80  ◎ 机灵 72  ☾ 灵气 80│
└──────────────────────────┘
```

版式约束：

- 主图明显大于信息区，猫咪始终是第一视觉焦点；
- 左侧的名字、品种和文案共用同一条左边线；
- MIKA 总分拥有独立的右侧列，不压住名字和文案；
- 三项属性等宽排列，按“图标 → 属性文字 → 数值”从各列左侧对齐；
- 不加长进度条、四个大圆章、底部横线堆叠或无意义装饰；
- 所有边线必须在 Canvas 内部绘制，不能超出画布或出现底部多余横线；
- 文字和数值不能依赖图片缩放后才可辨认。

### 7.3 五档等级皮肤

五档共用同一几何结构。先冻结以下色彩 token，具体颜色可在视觉验收时微调，但不能改变布局：

| 等级 | 外沿渐变 / 固定线条 | 信息区底色 | 文字色 | 气质 |
| --- | --- | --- | --- | --- |
| C | `#D5DFCC → #91A786` / 线条 `#8FA783` | `#FFFDF8` | `#354438` | 自然、日常 |
| U | `#E0D7E7 → #A696B2` / 线条 `#9A8AA9` | `#FFFDF8` | `#354438` | 柔和、轻快 |
| R | `#E8C894 → #BA8747` / 线条 `#B78445` | `#FFFDF8` | `#354438` | 温暖、有光 |
| SR | `#EBC1BC → #C27A72` / 线条 `#B96B65` | `#FFFDF8` | `#354438` | 明亮、心动 |
| UR | `#C4B6CF → #756483` / 线条 `#665378` | `#FFFDF8` | `#354438` | 安静、神秘 |

等级色只能出现在：外沿的轻微渐变、内侧固定描边、等级字母、少量固定强调点和图标强调色。渐变不得进入主图或信息区，不得把等级色扩散到猫咪照片；等级字母必须同时存在。

## 8. 动态文字和评分规则

### 8.1 文字显示

- 等级：只显示 `C / U / R / SR / UR`；中文等级名可作为很小的辅助信息，但不能替代代码；
- 档案编号：以右上角白字显示 `No. YYYYMMDD` + 6 位随机码，不显示 `catId`、recordId、fileID 或 openid；
- 名称：最多 8 个中文字符；过长使用展示副本，不覆盖档案原值；
- 品种和特征：作为次要信息，缺失时整行隐藏，不显示空占位符；
- 文案：使用档案已有 `posterCopy`，最多 36 个中文字符，固定占用 2 行；不足 2 行时保留空行，不推动评分区；
- 信息区垂直节奏固定：标题/MIKA 基线约在 `y=1149/1147`，文案基线为 `y=1201` 和 `y=1231`，指标行基线约为 `y=1288`；调整文字内容时不改变这些锚点；
- 没有海报文案时使用固定默认文案，例如“这次街角相遇，已经被轻轻收进档案里。”；
- 不把模型提示词、评分证据、识别置信度或技术状态写到海报。

### 8.2 分数显示

海报固定显示四个分数：

- `MIKA` 综合分 1 个；
- 三项构成分各 1 个；底部按固定顺序显示“图标 → 属性文字 → 数值”，不按分数重排；
- 四个值都必须是 0–100 的整数；
- 分数为 `0` 或没有分数时统一绘制 `0`，不绘制空白或 `--`；
- 三个属性顺序固定为：魅力 → 机灵 → 灵气；不能按分数高低重排；
- 不显示 `/100`、百分号、战斗力、价格或星级换算；
- 设计图中的 `100` 只能是排版占位，不能作为生产数据。

评分仍为 pending 或 coverage 不足时不阻断海报生成；缺失值按 `0` 绘制。等级仍优先使用档案保存值，没有保存值时使用 `C`。

### 8.3 图标

三项属性使用同一套线性图标：

1. 猫脸：魅力；
2. 眼睛：机灵；
3. 月牙：灵气。

图标规则：

- 三个图标使用同一网格、线宽、视觉尺寸和基线；
- 图标可以与等级色产生轻微强调，但不能改变语义顺序；
- 图标必须通过 SVG / Canvas Path 清晰绘制，不能从带白边的截图中抠取；
- 图标与数字之间保持固定间距，任何值从 `0` 到 `100` 都不能与图标重叠。

## 9. 保存和分享规则

### 9.1 海报预览页

成功渲染后进入预览页，预览页只接收已完成的 `posterResult`：

- 展示完整海报和生成状态；
- 提供“保存海报”和“分享海报”两个动作；
- 不在预览页再次生成主图或重新计算评分；
- 返回详情页时保留快照，但不强制写回档案；
- 生成失败时不展示残缺 Canvas，显示可重试和返回按钮。

### 9.2 保存到相册

- 使用最终导出的 PNG，不保存加载页截图；
- 保存前检查临时文件仍然存在，失效时只重新导出 Canvas，不重新调用图片生成；
- 用户拒绝相册权限时给出明确说明，允许返回预览，不循环弹窗；
- 文件名建议为 `猫咪咔咔-ARCHIVE-20240512XX11EE.png`，不得包含 openid 或完整云路径。

### 9.3 分享海报

“分享海报”有两个结果：

1. **分享图片**：使用最终 PNG 作为微信分享卡片的 `imageUrl`；
2. **分享落地页**：使用现有 `cat-archive-share` 生成或复用 `shareId`，落地到公开猫档案详情页。

分享规则：

- 分享前确保公开档案快照已经准备完成；
- `shareId` 只关联公开档案快照，不包含 openid；
- 分享参数使用生成海报时的 `posterData`，不能在分享回调里重新读取另一份最新数据；
- 接收者打开的是猫档案，不要求接收者拥有分享者的本地图片文件；
- 分享图可以包含档案编号、名字、等级、分数和猫图，但不包含精确地点、奖励余额和内部 ID；
- 分享到聊天和朋友圈使用同一张海报 PNG；落地 query 只携带 `shareId`；
- 原有的“分享猫档案”能力保留，海报分享是新增动作，不覆盖原分享行为。

## 10. 前端 / 云端职责

### 小程序端

- 从 `card-detail` 的标准化档案数据组装 `posterData`；
- 检查生成资格并创建 `posterJobId`；
- 预加载素材，驱动加载页状态；
- 调用图片适配服务或使用原图回退；
- 用 Canvas 2D 统一绘制预览和导出图；
- 校验文字、分数、比例和图片完整性；
- 保存到相册、调用分享 API。

### 云端

- 接收已通过安全检查的图片 fileID；
- 可选生成主图区域的合同比例图片，不生成文字海报；
- 返回图片版本、尺寸、请求 ID 和可读取的临时地址 / fileID；
- 公开分享只写入允许分享的快照字段；
- 不把 poster PNG 当作唯一数据源，历史海报需要保留 `posterData` 和版本记录才能复现。

### 建议新增模块

```text
miniprogram/utils/posterData.js       // 档案 → 海报快照
miniprogram/utils/posterResult.js     // 云端可复现海报结果的轻量快照
miniprogram/utils/posterCover.js     // 猫咪封面图云端调用
miniprogram/utils/posterCanvas.js     // Canvas 2D 渲染器和校验
miniprogram/utils/posterShare.js      // 海报 PNG + cat-archive-share
miniprogram/pages/poster-loading/     // 生成状态页
miniprogram/pages/poster-preview/     // 预览、保存、分享页
miniprogram/cloudfunctions/poster-cover/ // 无文字猫咪封面场景生成
```

现有 `catShare.js` 和 `cat-archive-share` 可以继续复用，但海报公开分享仍只传递公开快照；海报结果由 `sync-guest-data/save-poster-result` 写回所属 `encounters.media`，不直接把整个 `storage` 记录上传。

## 11. Canvas 合成伪代码

```text
onTapGeneratePoster()
  → checkPosterEligibility(archive)
  → navigate poster-loading with catId / sourceRecordId

poster-loading.onLoad()
  → read fixedPosterCache(sourceArchiveId, sourceRecordId, templateVersion)
  → if final poster PNG is still available:
       reuse fixed poster and navigate poster-preview
  → else posterData = buildPosterData(archive)
  → save immutable job snapshot
  → resolve featured image
  → if coverStatus is ready:
       useValidatedCover()
     else if local archive and original is usable:
       generatePosterCover(original, targetPhotoRatio)
     else:
       useOriginalPhoto()
  → renderPoster(posterData, image)
  → validatePoster(result)
  → if coverStatus is ready:
       save fixed poster cache
  → save posterResult to encounters.media.posterResult asynchronously
  → navigate poster-preview with result

renderPoster(data, image):
  create 750 × 1334 logical Canvas
  draw L1 background + one inside rarity border
  clip photo area
  drawCoverOrSubject(image, photoArea)
  draw L3 level code + archive code + fixed icon paths
  draw L4 name, breed, copy, MIKA and three scores
  validate no overflow / no overlap / no missing score
  export PNG at the same 9:16 ratio
```

`renderPoster()` 不调用评分函数、不生成文案、不修改档案。它只读取快照并绘制。

# 猫咪咔咔 — 首页说明 v0.1

> 状态：玩法与界面规则初稿
>
> 本文只定义首页的产品职责、页面状态和交互规则，不涉及具体代码实现。

## 1. 首页定位

首页是用户开始一次“相遇”的入口。

首页只完成两件事：

1. 告诉用户今天还剩多少个罐罐；
2. 让用户立即进入拍照流程。

首页不是数据中心，也不是图鉴首页。猫爪、咔咔分和猫咪识别结果在拍摄完成后的结果卡中展示，猫咪档案和历史记录分别放在图鉴页、我的页面中。

## 2. 核心玩法规则

### 2.1 罐罐

- 每位用户每天获得 3 个赠送罐罐；已购买且未使用的罐罐另行累计。
- 1 个罐罐对应 1 次拍照机会。
- 首页始终展示今日赠送额度的剩余数量，视觉上固定保留 3 枚罐罐图标；购买余额不追加到首页图标中。
- 打开相机不消耗罐罐。
- 用户按下快门并成功提交拍摄任务后，立即锁定并扣除 1 个罐罐。
- 识别结果为不是猫、图片模糊或主体不符合收录条件，均视为本次拍摄已发生，罐罐不返还。
- 只有服务端、存储、模型或系统异常导致任务无法处理时，才返还本次罐罐。
- 快门前取消、相机权限未开启且没有提交拍摄任务，不扣罐罐。
- 当天未使用的赠送罐罐暂不累积到下一天；购买余额不受每日重置影响。
- 每天 00:00 重置赠送额度为 3 个罐罐；首版按 Asia/Shanghai 自然日计算。

### 2.2 拍摄奖励

每次有效拍摄完成后，用户获得：

- 一张相遇卡：写入猫咪图鉴或相遇记录；
- 猫爪：经验值的产品名称，用于用户会员等级成长；五级名称和成长值见 [用户成长会员等级规则 v0.1](./MEMBER_LEVEL_RULES_V0_1.md)；
- 咔咔分：用于后续兑换、解锁、成就或其他玩法。

“咪咔”是相遇卡的综合评分，不是用户资产；“猫爪”才是经验奖励的显示名称。奖励不在首页领取，而是在拍摄结果卡中自动结算并展示，详见 [小猫评分与等级规则 v0.2](./CAT_SCORING_RULES_V0_2.md)。

### 2.3 猫咪收集

- 猫咪图鉴采用开放式收集，不预设固定数量。
- 新发现的猫咪动态创建档案。
- 已遇见的猫咪再次被拍摄时，增加相遇记录。
- 图鉴进度使用“已发现 X 只”，不使用“X / 60”。
- 卡片等级代码先使用五档：`C / U / R / SR / UR`。
- 中文等级名称和卡面短标签暂不写死，统一等待评分规则评审；咪咔与等级映射见 [小猫评分与等级规则 v0.2](./CAT_SCORING_RULES_V0_2.md)。
- 卡片等级描述的是这次相遇记录的特别程度，不代表猫咪本身有高低之分。`AR`、`SAR` 等名称未来可以作为特殊卡面样式或插画工艺，不作为卡片等级。

## 3. 页面结构

首页由四个区域组成：

```text
顶部品牌区
      ↓
今日罐罐区
      ↓
核心拍照区
      ↓
底部导航
```

### 3.1 顶部品牌区

内容保持轻量：

- 猫咪咔咔 Logo 或猫爪标记；
- 页面标题或简短品牌名；
- 可选展示用户等级，但不能抢占拍照入口的视觉重点。

推荐文案：

```text
猫咪咔咔
CITY CAT ARCHIVE
```

### 3.2 今日罐罐区

这是首页最重要的信息提示。

默认展示：

```text
今日剩余罐罐
● ● ●
还可以拍 3 次
```

使用一次后：

```text
今日剩余罐罐
● ● ○
还可以拍 2 次
```

展示要求：

- 3 个罐罐图标需要有明确的已使用 / 未使用状态；
- 数字和图标同时展示，不能只依赖颜色；
- 剩余数量要在进入首页时刷新；
- 从相机页返回后立即更新；
- 不展示复杂任务、排行榜或图鉴总进度。

### 3.3 核心拍照区

拍照区占据首页最大视觉面积，是唯一主操作。

建议包含：

- 大面积取景框或相机卡片；
- 猫爪、对焦框、胶带、纸张等轻量装饰；
- 中央主按钮“拍照”；
- 一句不打扰猫咪的提示语。

推荐文案：

```text
去遇见一只猫
保持一点距离，不打扰它

[ 拍照 ]
```

点击取景区域或拍照按钮，都进入相机页。

### 3.4 底部导航

底部保留三个页面入口：

```text
相遇    图鉴    我的
```

首页的“相遇”保持选中状态。底部导航可以进入图鉴和我的页面，但首页主体不放置额外的图鉴卡片或历史记录列表。

## 4. 首页状态

### 4.1 还有 3 个罐罐

```text
今日剩余罐罐 3 / 3
● ● ●

[ 拍照 ]
```

拍照按钮正常可用。

### 4.2 还有 1–2 个罐罐

```text
今日剩余罐罐 2 / 3
● ● ○

[ 拍照 ]
```

继续允许进入相机，不能因为已经拍过一次就阻止用户继续拍摄。

### 4.3 罐罐已用完

```text
今日罐罐已用完
○ ○ ○

今天的 3 个免费罐罐已经用完
[ 去充值 ]   [ 知道了 ]
```

拍照按钮变为不可用状态，点击时展示引导弹窗；点击“去充值”进入用户中心并自动打开套餐选择，点击“知道了”关闭提示，不进入相机。首页仍只展示 3 枚每日罐罐图标，购买余额在用户中心单独累计。

### 4.4 正在刷新额度

从相机页返回、应用重新打开或跨过 00:00 时，先重新读取当天额度。刷新完成前，拍照按钮短暂禁用，避免重复点击造成多次扣除。

## 5. 拍照交互流程

```text
用户进入首页
  ↓
读取今日剩余罐罐
  ↓
用户点击拍照区
  ↓
判断剩余数量是否大于 0
  ├─ 否：提示“今日罐罐已用完”
  └─ 是：进入相机页
          ↓
       用户按下快门
          ↓
       锁定并扣除 1 个罐罐
          ↓
       上传并处理照片
          ↓
       识别结果 / 异常处理
          ├─ 识别不是猫 / 图片不合格：罐罐不返还，展示失败原因
          ├─ 服务异常：返还罐罐
          └─ 识别成功：进入相遇结果卡并发放猫爪、咔咔分
          ↓
       返回首页后更新剩余数量
```

## 6. 扣除和失败规则

### 已提交拍摄但识别未通过

- 快门提交成功；
- 罐罐已经扣除；
- 识别不是猫、图片过于模糊或主体不符合收录条件：不生成相遇卡，不发猫爪和咔咔分；
- 展示失败原因和“今天还剩 X 个罐罐”，不自动返还。

### 服务或系统异常

只有服务端能够确认属于产品侧异常时，才返还罐罐，例如：

- 任务已受理后，服务端处理链路创建或执行失败；
- 图片存储或处理服务不可用；
- 内容安全或识别模型服务异常、超时；
- 结算服务异常，无法完成本次任务。

处理方式：

```text
异常提示 → 本次罐罐返还 → 用户可以重新拍摄
```

相机权限失败、快门前取消属于“没有提交拍摄任务”，本来就不扣罐罐。用户在快门后退出页面时，任务仍按已提交处理；重新打开时先查询原任务状态，不能因为结果页没有打开就自动返还。

### 重复点击

用户连续点击拍照按钮时，只创建一个拍摄任务。任务处理中按钮进入 loading 状态，避免重复扣除额度和重复发奖。

## 7. 首页不展示的内容

以下内容暂时不放在首页：

- 固定猫咪总数，例如 60 只；
- 图鉴完成百分比；
- 复杂任务系统；
- 猫爪和咔咔分明细；
- 猫咪历史记录列表；
- 排行榜和社交动态；
- 多个并列的主按钮。

首页只保留一个清晰动作：

> 看见剩余罐罐，拍一只猫。

## 8. 待确认事项

以下内容不影响首页结构，但需要在奖励系统设计时确定：

- 咔咔分的兑换规则；
- 会员等级的后续展示权益（五级名称与成长值已见 [用户成长会员等级规则 v0.1](./MEMBER_LEVEL_RULES_V0_1.md)）；
- 识别到“不是猫”时是否消耗罐罐；
- 识别到猫但品种不确定时的奖励；
- 未使用罐罐是否永远不累积；
- 每日重置时间是否固定为 00:00。

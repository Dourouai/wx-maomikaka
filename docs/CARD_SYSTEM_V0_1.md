# 猫咪咔咔 — 相遇卡规则与五级卡面样式 v0.1

> 当前阶段：卡片玩法与视觉结构设计稿
>
> 本文先定义卡片的生成规则、信息层级、正反面结构和五套视觉主题，不涉及代码实现。

五套样式的视觉对照见 [五级卡面样式对照板 V4](./CARD_STYLES_BOARD_V4.png)；V1–V3 保留作为早期版本。

## 1. 卡片的定位

相遇卡是用户每次成功记录一只猫后获得的收藏结果。它参考集换式卡片的“编号、等级、属性、卡面”结构，但不做战斗、攻击、防御或卡牌对战。

卡片记录的是：**这一次在哪里、以什么状态遇见了这只猫。**

卡片等级来自本次相遇的 `咪咔`，不是猫咪本身的固定身价，也不代表猫咪有高低之分。

## 2. 卡片和编号的关系

一张成功的相遇卡包含三层身份：

```text
cardNo   = 这一次相遇卡的唯一编号
imageId  = 这一次使用的图片编号
catId    = 这只猫咪档案的稳定编号
```

规则：

- 每次识别成功并完成结算，生成 1 张新的相遇卡；
- 同一只猫再次被拍到，复用 `catId`，但生成新的 `imageId` 和 `cardNo`；
- 不是猫、图片不合格或服务异常，不生成相遇卡；
- `cardNo` 永不复用，卡片隐藏后编号仍然保留；
- 图鉴按 `catId` 聚合，卡片详情保留每一次相遇记录；
- 不预设固定猫咪总数，也不使用“还差多少张卡”的强制收集表达。

编号格式沿用 [图片与相遇卡编号规则](./ID_RULES_V0_1.md)，例如：

```text
No. MK-260902-000014
CAT-000378
```

## 3. 卡片生成流程

```text
按下快门并提交任务
  ↓
扣除 1 个罐罐
  ↓
识别出一只可收录的目标猫
  ↓
计算魅力 / 机灵 / 灵气
  ↓
计算咪咔并映射 C / U / R / SR / UR
  ↓
生成 cardNo，选择对应卡面主题
  ↓
保存相遇卡、猫咪档案和本次相遇记录
```

识别结果不是猫或不符合收录条件时，只结束本次拍摄，不生成卡片；服务异常时返还罐罐，也不生成卡片。

## 4. 卡片统一结构

五个等级使用同一套版式，避免像五个不同产品。卡片主视觉统一采用“猫咪 + 环境背景”的连续场景图；不同等级主要改变场景色调、卡框、信息牌、装饰符号和揭示动效。

### 4.1 正面信息层级

```text
┌────────────────────┐
│ C       CAT FOUND  │  ① 等级代码 / 结果眉题
│ No. MK-260902-...  │  ② 相遇卡编号
│                    │
│    猫咪 + 背景场景图  │  ③ 主视觉，占卡面约 65%–70%
│                    │
│ 橘色小家伙          │  ④ 猫咪名称
│ #橘猫  #尾巴蓬蓬     │  ⑤ 轻量标签，最多 2–3 个
│                    │
│       咪咔 75       │  ⑥ 综合分，视觉焦点
│ 魅力 82  机灵 70    │  ⑦ 三项数值摘要
│ 灵气 74             │
│         · CAT ARCHIVE│ ⑧ 品牌签名
└────────────────────┘
```

正面必须保留：

- 猫咪与环境背景组成的场景图；
- 等级代码；
- 猫咪名字；
- 咪咔；
- 卡片唯一编号。

正面不放：

- 猫爪和咔咔分奖励数值；
- 用户的罐罐余额；
- 复杂模型说明；
- 精确 GPS 位置；
- 战斗属性、攻击力、防御力或价格感标签。

猫爪和咔咔分属于本次拍摄的结算奖励，在结果页单独展示，不让卡片看起来像兑换券。

场景图不是单独抠出的猫咪贴纸：猫咪要和街巷、窗台、店铺、屋顶或夜景形成空间关系，让用户收藏的是“这只猫出现在这个地方的瞬间”。背景可以适度虚化，但不能被纯色块完全替代。第一版视觉稿按“场景图约 65%–70% + 底部信息牌约 25%–30%”执行。

### 4.2 背面 / 详情页

背面适合放更完整的猫咪档案：

```text
猫咪档案 CAT-000378

稳定特征
橘色短毛 · 左耳小缺口 · 尾巴环纹

这次相遇
2026.09.02 · 上海
本猫第 3 次被遇见

魅力 82   机灵 70   灵气 74
咪咔 75 · [等级代码]

这是一只在街角停下来晒太阳的猫。
```

地点只展示城市或用户主动填写的模糊区域，不展示可反推出住址的精确坐标。

## 5. 五套卡面样式

本稿按当前的 `C / U / R / SR / UR` 五档设计。如果基础档最终从 `C` 改为 `N`，只替换代码，不需要重做卡面主题。

下面的名称是**视觉主题名**，不是最终中文等级名称；最终等级标签仍由命名规则单独确认。

| 代码 | 视觉主题名 | 主颜色 | 辅助颜色 | 主要符号 | 卡面气质 |
| --- | --- | --- | --- | --- | --- |
| C | 薄荷留影 | `#DCEAD8` 薄荷绿 | `#52745C` 苔藓绿 | 取景角 + 小圆点 | 轻、干净、第一次记录 |
| U | 云朵探头 | `#E3DDF2` 云朵紫 | `#75668A` 灰紫 | 两片小叶 + 探头弧线 | 软、俏皮、有一点意外 |
| R | 蜜糖闪现 | `#F7E2AD` 蜜糖黄 | `#A66E2C` 暖金棕 | 四角小星 + 纸箔边 | 温暖、难得、带一点闪 |
| SR | 珊瑚星轨 | `#F5D4D4` 珊瑚粉 | `#B9544A` 猫爪珊瑚 | 星轨弧线 + 爱心星点 | 明亮、心动、短暂高光 |
| UR | 月光神隐 | `#40304E` 夜幕紫 | `#F2C671` 月光金 + `#FF8F79` 珊瑚光 | 月轮 + 星点 + 猫爪印 | 神秘、梦幻、最高辨识度 |

### 5.1 C｜薄荷留影

- 场景图：橘色猫坐在薄荷绿调的安静街巷里，保留石板路、植物和门窗等环境信息；
- 卡底：奶油白纸张，叠一块薄荷绿观察记录区；
- 边框：单层苔藓绿细线，不使用发光；
- 装饰：四角取景线、两三个小圆点，像刚完成的一次观察记录；
- 场景图：保持真实原色，不加会改变猫咪毛色的滤镜；
- 动效：卡片轻轻上浮，咪咔数字淡入；
- 适合表达：日常、自然、没有压力的第一次相遇。

### 5.2 U｜云朵探头

- 场景图：灰白猫从云朵紫调的窗台探出头，保留窗帘、植物和远处天空；
- 卡底：奶油白叠云朵紫软角块；
- 边框：双层圆角线，局部有一条像猫从角落探出的弧线；
- 装饰：小叶、半颗爱心或两颗不对称星点；
- 场景图：比 C 多一层柔和紫色外框，但不切断猫咪和窗台的空间关系；
- 动效：边角贴纸微微弹一下，随后恢复；
- 适合表达：比日常多一点巧合和俏皮。

### 5.3 R｜蜜糖闪现

- 场景图：三花猫出现在蜜糖色店铺门口，保留遮阳棚、砖墙和街道光线；
- 卡底：暖奶油色，场景图下方使用淡蜜糖黄信息板；
- 边框：细暖金边，四角只保留一到两颗四角星；
- 装饰：小纸箔、短闪光线，不做满屏金色；
- 场景图：允许轻微暖色提亮，但不改变猫咪毛色和背景层次判断；
- 动效：揭示时出现一次短促的星光闪烁；
- 适合表达：难得遇见、画面里有一个特别瞬间。

### 5.4 SR｜珊瑚星轨

- 场景图：黑白猫走过珊瑚粉夕阳下的屋顶或楼梯平台，背景保留天空和城市轮廓；
- 卡底：奶油白 + 珊瑚粉分区，主标题使用猫爪珊瑚；
- 边框：柔和珊瑚双线，边缘加入一条不闭合的星轨弧线；
- 装饰：爱心星点、短尾迹、轻微叠纸层；
- 场景图：外框可以使用珊瑚渐变，但不在猫咪和背景上叠加大量粒子；
- 动效：星轨绕卡片边缘走一小段后停止；
- 适合表达：一眼心动、转瞬即逝的高光相遇。

### 5.5 UR｜月光神隐

- 场景图：白橘猫停在夜幕紫的屋顶，保留月亮、远处城市和屋顶纹理；
- 卡底：夜幕紫卡框，内部仍保留奶油白信息区，避免整张卡过暗；
- 边框：月光金细边 + 珊瑚色小高光，形成柔和的深浅反差；
- 装饰：不完整月轮、少量星点和一枚小猫爪印；
- 场景图：只允许轻微月光晕染，猫咪真实细节和背景空间优先；
- 动效：揭示时月轮亮起，星点出现，再停留在静态卡面；
- 适合表达：非常少见的气质和不可复制的相遇感。

UR 不使用爆炸、火焰、皇冠或满屏金色。最高等级的特别感来自“安静、深色、留白和月光”，保持猫咪咔咔的温柔气质。

## 6. 等级颜色使用规则

等级颜色只服务于识别和收藏，不表达价格或战斗力：

- 猫咪与背景场景图永远优先，等级色只能出现在卡框、标签、分数和少量装饰上；
- 同一等级的卡片颜色保持稳定，猫咪和背景照片不能决定等级色；
- C / U 使用低饱和色，保证日常卡不会显得廉价或被“低级”羞辱；
- R / SR / UR 逐步增加高光，但每一级只增加一种主要视觉记号；
- 文本不能只靠颜色传达等级，始终同时展示 `C / U / R / SR / UR` 代码；
- 深色 UR 卡必须保证正文、编号和按钮达到清晰对比度；
- 动效可关闭，静态卡面仍必须完整表达等级。

## 7. 卡片与结果页的分工

```text
结果页：告诉用户这次得到了什么
  ├─ 相遇卡
  ├─ 咪咔与等级
  ├─ 猫爪奖励
  ├─ 咔咔分奖励
  └─ 新勋章

图鉴卡：让用户回看遇见过谁
  ├─ 猫咪 + 背景场景图
  ├─ 名字与等级
  ├─ 咪咔
  └─ cardNo
```

结果页可以让卡片先揭示，再从卡片下方出现 `猫爪 +115` 和 `咔咔分 +8`。保存到图鉴后的卡片不重复播放奖励动画。

## 8. 卡片交互

### 8.1 揭示

- C / U：轻微上浮和淡入；
- R：一次短星光；
- SR：一段短星轨；
- UR：月轮亮起后停住；
- 所有等级的动效时长控制在 0.4–0.8 秒；
- 用户可以跳过动效，直接查看完整卡片。

### 8.2 翻看详情

- 点击卡片：正面与档案详情之间翻看；
- 详情页显示完整 `cardNo`、`catId`、三项数值和相遇时间；
- 不把模型置信度、内部错误码和图片文件编号放到第一层；
- 分享图优先导出正面，不默认附带用户罐罐余额或奖励余额。

### 8.3 同猫重复相遇

- 新卡进入同一 `catId` 档案的“相遇记录”；
- 图鉴主卡默认展示最佳照片或最近一次照片，由用户选择；
- 每张历史相遇卡保留自己的等级、咪咔、照片和 `cardNo`；
- 同一只猫不会因为重复拍摄自动升级，只有本次相遇重新计算分数。

## 9. 首版规则边界

首版先确定：

1. 一次识别成功 = 一张相遇卡；
2. 相遇卡使用统一版式 + 五套等级主题；
3. 卡片等级由咪咔映射，沿用 `C / U / R / SR / UR` 代码；
4. 猫咪与真实环境场景是主视觉，等级色不覆盖主体；
5. 卡片本身不承载猫爪、咔咔分等经济奖励；
6. 卡片唯一编号使用 `cardNo`，猫咪档案使用 `catId`；
7. 中文等级名称、最终字体和印刷工艺留到下一轮确认。

## 10. 下一步设计任务

- 用五个不同场景的猫咪图分别套入统一卡框，比较“猫 + 背景”是否形成收藏记忆点；
- 细化场景图裁切规则：竖图、横图、猫咪太小、多猫和背景过乱；
- 设计一张结果揭示页，把卡片、猫爪、咔咔分和勋章放在同一条交互节奏里；
- 最后再确认五档中文等级名称和是否使用 `C` 或 `N` 作为基础档代码。

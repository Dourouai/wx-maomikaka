# 猫咪咔咔 — 五级相遇卡 Canvas 分层与版式规则 v0.1

> 当前阶段：卡片模板开发交接稿
>
> 本文只定义卡片如何拆层、放置图片和文字，不涉及具体 Canvas 代码实现。

当前视觉参考：[五级卡面样式对照板 V9](./CARD_STYLES_BOARD_V9.png)。

## 1. 设计结论

每个等级是一套独立模板，但五套模板使用同一套信息坐标。开发时不是把五张成品图直接放进 Canvas，而是按照同一张卡的五层结构合成：

```text
每个等级模板
  ├─ L1 底纸与色板
  ├─ L2 背景图槽位
  ├─ L3 猫咪图槽位
  ├─ L4 卡框与等级装饰
  └─ L5 信息文字与数值
```

可变化的内容只有：

- 背景图片；
- 猫咪图片或猫咪抠图；
- 猫咪名字；
- 相遇短笺；
- 等级、编号、咪咔、魅力、机灵、灵气等文字和数值。

颜色、卡框、纸张纹理、等级装饰、属性图标和信息牌形状都属于模板固定内容，不由单次识别结果临时改变。

## 2. Canvas 基准尺寸

### 2.1 设计尺寸

| 项目 | 规则 |
| --- | --- |
| 逻辑画布 | `750 × 1050 px` |
| 卡片比例 | `5 : 7` |
| 导出建议 | `1500 × 2100 px`，按设备像素比放大 |
| 外边距安全区 | 32 px |
| 卡片圆角 | 28 px |
| 内容最小字号 | 18 px，不低于此值 |
| 正文建议字号 | 20–22 px |
| 所有动态文字 | 由 Canvas 绘制，不烘焙进模板图片 |

### 2.2 统一信息坐标

以下坐标以 `750 × 1050` 逻辑画布为准。五个等级只替换视觉皮肤，不改变信息槽位。

| 区域 | x | y | w | h | 内容 |
| --- | ---: | ---: | ---: | ---: | --- |
| 卡片安全区 | 32 | 32 | 686 | 986 | 所有核心内容不得越过 |
| 顶部标题区 | 32 | 32 | 686 | 86 | 等级标签、卡号 |
| 等级标签 | 44 | 38 | 194 | 58 | `SR · 惊鸿` |
| 唯一编号 | 255 | 54 | 430 | 24 | `No. MK-260903-000014`，右对齐 |
| 场景图窗口 | 32 | 116 | 686 | 594 | 猫咪 + 背景主视觉 |
| 名字纸签 | 48 | 650 | 410 | 92 | 按 5 个字宽度预留 |
| 咪咔主徽章 | 550 | 630 | 152 | 120 | `咪咔 84`，与名字牌叠放 |
| 相遇短笺区 | 32 | 758 | 686 | 72 | 50 字以内，最多 3 行 |
| 三项属性区 | 32 | 842 | 686 | 126 | 三个图标 + 三个数值 |
| 品牌签名 | 32 | 1010 | 686 | 24 | `CAT ARCHIVE` |

场景图窗口是唯一的大图区域，建议占卡面视觉面积的 56%–60%，并允许名字牌和咪咔徽章压住图片下沿。底部信息区必须为名字、四个数值和短文案留出完整空间。

## 3. 五层合成规则

### L1｜底纸与色板层

固定模板层，铺满整个卡片。

- 负责纸张底色、卡片圆角、基础纸纹和等级主色；
- 不放动态文字，不放猫咪，不放编号；
- C / U 使用低饱和浅色，R / SR 增加暖色和压印感，UR 使用深色底但保留浅色信息区；
- 纸纹透明度保持克制，不能影响文字识别。

### L2｜背景图槽位

动态图片层，由 Canvas 放入本次相遇的环境背景。

- 只在场景图窗口内显示，并使用统一圆角裁切；
- 默认使用 `cover` 思路填满窗口，不能出现空白边；
- 裁切优先保留门、窗、屋顶、街巷、植物和光线等环境线索；
- 背景可以按等级做轻微色彩处理，但不能把真实环境变成纯色块；
- 如果传入的是已经包含猫咪的完整照片，L3 关闭，直接由 L2 承载整张照片。

### L3｜猫咪图槽位

动态图片层，由 Canvas 放入猫咪抠图或主体图片。

- 猫咪保持原始比例，不拉伸、不压扁；
- 猫脸、耳朵和主要动作不能被 L4 装饰遮挡；
- 猫咪主体建议占场景窗口高度的 40%–72%，过小会失去收藏识别度；
- 如果没有可靠抠图，不强行拆分，使用“猫咪 + 背景”完整相遇图；
- L3 与 L2 的光线方向需要一致，不能出现明显的贴纸拼接感。

### L4｜卡框与等级装饰层

固定模板层，覆盖在场景图上方。

- 负责场景图边框、等级徽章外形、纸签形状、等级装饰、局部压印和固定图标底板；
- 等级代码与中文等级名的底板固定在左上区域；
- 装饰可以靠近边缘和信息区，但不能穿过猫脸、眼睛和关键动作；
- 三个属性图标的轮廓固定，颜色固定，不跟随等级换色；
- 该层不写入卡号、名字、分数和文案，避免每张图重新生成模板。

### L5｜信息文字与数值层

由 Canvas 动态绘制的最上层。

固定槽位中写入：

- 等级代码和中文等级名；
- `cardNo` 唯一编号；
- 猫咪名字；
- `咪咔`、`魅力`、`机灵`、`灵气`四个数值；
- 50 字以内的「相遇短笺」；
- `CAT ARCHIVE` 等固定小字。

L5 不绘制奖励信息，不绘制罐罐余额，不绘制模型置信度，不绘制 GPS。

## 4. 动态内容的数据槽位

```text
backgroundImage  = 环境背景图，可与 catImage 合并
catImage         = 猫咪抠图，可为空
name             = 猫咪名字，最多 5 个字
copy             = 相遇短笺，最多 50 个中文字符
levelCode        = C / U / R / SR / UR
levelName        = 街角 / 偶见 / 稀遇 / 惊鸿 / 神隐
cardNo           = No. MK-YYMMDD-NNNNNN
mika             = 咪咔综合分
charm            = 魅力值
cleverness       = 机灵值
aura             = 灵气值
```

正式卡面的四个分数只写实际结果，例如：

```text
咪咔 84
魅力 80 · 机灵 83 · 灵气 89
```

不写 `100`、`/100`、百分比、星级换算或进度条。内部评分仍然按照 0–100 的范围计算，但上限不是卡面内容。

## 5. 五个等级的图片位置与风格

五个等级共用场景图窗口坐标，但对图片的主体位置、环境留白和色彩处理有不同要求。

| 等级 | 背景图风格 | 猫咪位置 | 场景图处理 | 固定装饰语言 |
| --- | --- | --- | --- | --- |
| C · 街角 | 明亮自然的街巷、窗台、门边 | 下方居中，主体约占窗口高度 40%–50% | 保持原色，轻微提亮，不加发光 | 邮票齿孔边、取景角、薄荷便签 |
| U · 偶见 | 柔和窗帘、墙角、低矮花坛 | 从左侧或右侧探出，主体约占 35%–48% | 紫色环境氛围轻轻叠加，保留真实光线 | 云朵切口、错位贴纸、软胶标签 |
| R · 稀遇 | 暖色店门、砖墙、阳光入口 | 中间偏下，主体约占 50%–65% | 加暖金光线和局部纸箔感，不改变毛色 | 斜向金箔带、压印边、太阳切面章 |
| SR · 惊鸿 | 珊瑚夕阳、屋顶、楼梯和风 | 画面三分线附近，主体约占 52%–65% | 保留运动方向和留白，让轨道绕开猫脸 | 轨道弧线、半透明带、圆珠节点 |
| UR · 神隐 | 月光屋顶、夜景、安静建筑 | 下方或下侧，主体约占 35%–50% | 深色环境加月光边缘，保留猫咪细节 | 月门拱框、月光金边、稀疏星点 |

### 5.1 图片裁切安全区

- 猫脸安全区：场景窗口中心横向 20%–80%、纵向 12%–78%；
- 重要动作安全区：不得被等级徽章、轨道、金箔带或月门内框遮挡；
- 背景留白区：至少为场景窗口面积的 15%，用于保持画面呼吸和等级装饰；
- 多猫图片不自动拆成多张卡，必须先由识别流程确定目标猫；
- 图片比例异常时优先裁切背景边缘，不裁掉猫脸、耳朵和尾巴动作。

### 5.2 等级装饰不可越界

等级装饰只允许出现在四类区域：

1. 卡片外边框；
2. 场景图边缘的空白区域；
3. 名字、咪咔和属性信息牌周围；
4. 卡片四角的少量固定符号。

装饰不得覆盖猫咪脸部、眼睛、耳朵、四肢关键动作和相遇短笺正文。

## 6. 信息排版与占位状态

### 6.1 名字

- 输入框占位符：`给猫咪取名`；
- 最多 5 个字，超过后直接阻止继续输入；
- 名字纸签按 5 个字的标准宽度设计；1–4 个字保持视觉居中，不改变纸签宽度；
- 未填写时卡片显示：`未命名`；
- 名字使用纸签区域，不因为字数不同改变卡框和其他槽位；
- 五个字时缩小字号，不使用省略号截断。

### 6.2 分数

- 计算中：`咪咔 —`、`魅力 —`、`机灵 —`、`灵气 —`；
- 待评估或证据不足：`咪咔 待评估`，三个属性显示 `—`；
- 完成后替换为实际整数；
- `0` 可以作为真实计算结果，但不能作为“还没算出来”的占位；
- 服务异常、不是猫或拍摄失败，不生成带分数占位的相遇卡。

### 6.3 等级与编号

- 正式完成卡：显示 `代码 · 中文名`，例如 `SR · 惊鸿`；
- 评分未完成：顶部使用中性标签 `待评估`，不提前伪造 C / U / R / SR / UR；
- 正式完成卡必须显示完整 `cardNo`，例如 `No. MK-260903-000014`；
- 编号生成前只显示 `编号生成中`，不能把临时编号保存为正式卡号；
- `cardNo` 一旦生成，不因用户改名字或重新排版而变化。

### 6.4 相遇短笺

- 标题固定为「相遇短笺」；
- 最多 50 个中文字符，建议控制在 30–45 字；
- 正文最多 3 行，行距建议 30 px；
- 文案只描述照片中可见的猫咪、动作、光线和环境；
- 文案缺失时显示：`正在整理这次相遇……`，不输出空白卡片。

## 7. Canvas 合成顺序

```text
1. 创建 750 × 1050 逻辑画布
2. 绘制 L1：底纸、色板、圆角卡片
3. 裁切场景图窗口，绘制 L2 背景图
4. 若存在猫咪抠图，按该等级的主体锚点绘制 L3 猫咪图
5. 绘制 L4 卡框、等级徽章、装饰和固定图标底板
6. 绘制 L5 等级文字、编号、名字、咪咔、三个属性和相遇短笺；名字牌与咪咔徽章允许压住场景图下沿
7. 检查文字是否越界、猫脸是否被遮挡、四个分数是否齐全
8. 按设备像素比导出最终图片
```

合成后必须满足：

- 猫咪和背景仍然是一段完整场景，不像单独贴纸；
- 等级标签、编号和名字一眼可见；
- 四个分数都存在且没有上限符号；
- 文案不超过 50 字，不挤压咪咔和属性区；
- 五套风格的主要差异来自 L1 / L4，而不是临时给照片套滤镜。

## 8. 开发交接边界

### 模板侧提供

- C / U / R / SR / UR 五套 L1 底纸资源；
- 五套 L4 卡框与等级装饰资源；
- 三项属性图标的统一资源；
- 场景图窗口的圆角和安全区规范；
- 五套图片构图和色彩处理说明。

### Canvas 侧负责

- 放入背景图和猫咪图；
- 绘制名字、相遇短笺、编号、等级标签和四个分数；
- 执行文本换行、字号适配和占位状态；
- 检查图片裁切、文字越界和遮挡关系；
- 导出分享图或图鉴卡图。

### 不在卡片 Canvas 中处理

- 猫爪、咔咔分、罐罐余额等奖励；
- 模型置信度、识别错误码和详细生物特征；
- 用户 GPS、精确地址和后台调试信息；
- 动态改变等级颜色或随机改变卡框装饰。

## 9. 当前确认项

1. 卡片为单面设计，不制作反面；
2. 五个等级各自有模板皮肤，但统一信息坐标；
3. 每张卡拆成五层合成，动态内容只进入图片槽位和文字槽位；
4. 名字最多 5 个字，占位为「给猫咪取名」，空状态为「未命名」；
5. 分数内部范围为 0–100，卡面只显示实际数字或占位符；
6. 正式卡固定展示等级标签、唯一编号、名字、四个分数和 50 字以内文案；
7. 五套风格分别使用薄荷、云朵紫、蜜糖、珊瑚和月光深紫的固定视觉模板。

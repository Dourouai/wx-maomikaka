# 猫咪咔咔 — 小猫评分与等级规则 v0.2

> 参考基线：[小猫评分与等级规则 v0.1](./CAT_SCORING_RULES_V0_1.md)
>
> 本版目的：把现有的“魅力 / 机灵 / 灵气”细化为可由 GLM 观察、由服务端计算、可以持续校准的相遇评分规则。

## 1. 评分对象先分开

本系统同时存在三类信息，但它们不能互相替代：

| 信息 | 含义 | 是否影响本次相遇评分 |
| --- | --- | --- |
| 猫咪身份特征 | 花纹、脸部记号、视觉身份向量等，用于判断是否为同一只现实猫 | 否 |
| 图鉴角色稀有度 | `catData.rarity` 等固定卡面/角色属性 | 否 |
| 相遇表现评分 | 这张照片里呈现出的魅力、机灵和灵气 | 是 |

**咪咔代表“这一次相遇有多特别”，不代表这只猫的生命价值、价格、品种等级或真实智商。**同一只猫再次被拍摄时，可以得到不同的相遇分，但仍然复用同一个现实猫咪档案 `catId`。

## 2. 三项正式指标

三项均为 `0–100`，使用等权重：

| 指标 | 键名 | 权重 | 评分对象 | 明确不评价 |
| --- | --- | ---: | --- | --- |
| 魅力值 | `charm` | 1/3 | 当前照片的表情、姿态、外观呈现和亲和氛围 | 美丑、价格、品种高低 |
| 机灵值 | `cleverness` | 1/3 | 当前照片里可见的观察、反应、动作和环境适应 | 科学意义上的智商、训练程度 |
| 灵气值 | `aura` | 1/3 | 当前画面的神态、辨识感、姿态气场和场景氛围 | 神秘力量、血统优越、稀有度 |

评分只使用图片中可见证据。GLM 可以描述证据，但不能把“品种稀有”“看起来贵”“像某个传说角色”当成加分理由。

## 3. 分项评分公式

GLM 不直接决定最终分数，而是先返回每个子项的 `0–100` 观察分；服务端按照固定权重计算三项总分。这样可以审计、复算和调整规则。

### 3.1 魅力值 `charm`

```text
魅力值 = 表情与眼神 × 35%
       + 姿态表现 × 25%
       + 外观呈现 × 25%
       + 亲和氛围 × 15%
```

子项解释：

- 表情与眼神：眼神、耳朵朝向、面部状态是否形成清楚的画面吸引力；
- 姿态表现：坐、趴、回头、伸懒腰等姿势是否完整且有表现力；
- 外观呈现：毛色、轮廓和可见细节在照片中是否清晰，不是评价“好不好看”；
- 亲和氛围：猫与镜头、光线和周围空间是否形成舒服的互动感。

### 3.2 机灵值 `cleverness`

```text
机灵值 = 观察眼神 × 35%
       + 反应与姿态 × 30%
       + 动作灵活度 × 20%
       + 环境适应感 × 15%
```

子项解释：

- 观察眼神：是否表现出正在观察镜头或周围变化；
- 反应与姿态：回头、停顿、警觉、探头等对当下刺激的可见反应；
- 动作灵活度：跳跃、转身、行走或身体控制在当前画面中的表现；
- 环境适应感：在台阶、窗台、墙角、街巷等环境中呈现的自然程度。

静态趴着不等于机灵值低；只要图片呈现出清楚的观察或反应证据，就可以得到相应分数。

### 3.3 灵气值 `aura`

```text
灵气值 = 神态感染力 × 35%
       + 花纹与五官组合 × 30%
       + 姿态气场 × 20%
       + 场景氛围 × 15%
```

子项解释：

- 神态感染力：神态是否让人产生明确、持续的观看记忆；
- 花纹与五官组合：只评价当前画面中的辨识度，不把固定图鉴稀有度搬进来；
- 姿态气场：姿态、轮廓和留白是否形成鲜明的存在感；
- 场景氛围：猫与光线、建筑、植物或街道是否形成完整的瞬间。

“辨识度”只表示这张照片是否容易记住，不表示猫咪比另一只猫更有价值。

## 4. 子项评分锚点

为了减少 GLM 每次随意打分，所有子项都使用同一组粗粒度锚点：

| 分数区间 | 观察含义 |
| ---: | --- |
| 0–19 | 几乎不可见、没有有效证据，或主体严重受遮挡 |
| 20–39 | 证据很弱，只能看出一点倾向 |
| 40–59 | 普通、可确认但没有明显突出表现 |
| 60–79 | 证据清楚，画面中有明确表现 |
| 80–94 | 表现突出，细节和画面关系都很清楚 |
| 95–100 | 极少见的完整高质量表现，必须能指出具体证据 |

`95–100` 不能因为“看起来可爱”直接给出，GLM 必须同时返回可解释的观察依据。没有依据时，子项最高建议不超过 `79`。

## 5. 证据与质量门槛

### 5.1 识别前置条件

以下条件不满足时，不进入正式评分：

- 图片安全检查通过；
- 只确认一只目标猫；
- 猫咪主体位置明确；
- 主体没有严重模糊、过小或大面积遮挡；
- 至少能观察到三项评分中的主要证据。

不是猫、多猫未选定目标猫、图片不可读取或服务异常，分别走现有失败/返还规则，不通过低分伪装成普通相遇。

### 5.2 证据覆盖率

每一项评分包含四个子项。服务端应保存：

```json
{
  "scoreVersion": "cat-score.v0.2",
  "scoreEvidence": {
    "charm": {
      "expression": 82,
      "posture": 74,
      "appearance": 68,
      "affinity": 61
    },
    "cleverness": {
      "observation": 78,
      "reaction": 66,
      "agility": 52,
      "adaptation": 70
    },
    "aura": {
      "expression": 76,
      "patternFace": 64,
      "presence": 72,
      "scene": 69
    }
  },
  "scores": {
    "charm": 73,
    "cleverness": 68,
    "aura": 71
  }
}
```

服务端负责计算 `scores`，客户端只负责展示。缺失子项不应默认成高分；如果证据覆盖不足，应标记 `scorePending=true`，使用基础占位分仅用于演示，不应据此发放高等级奖励。

### 5.3 图片质量不直接等于低分

严重模糊、主体太小和遮挡首先影响“是否可评分”，不应简单把它们变成猫咪魅力低。质量不合格的照片按拍摄有效性规则处理；服务端异常按罐罐返还规则处理。

## 6. 咪咔计算

三项等权：

```text
咪咔 = round((charm + cleverness + aura) / 3)
```

结果范围为 `0–100`。数据库保存三项分、总分、评分版本和证据；结果卡只需要展示咪咔与三项摘要。

示例：

```text
魅力 74 + 机灵 67 + 灵气 70
咪咔 = round(211 / 3) = 70
```

## 7. 五档相遇等级

等级只描述本次相遇卡，不描述现实猫咪的高低：

| 代码 | 咪咔范围 | 附加条件 | 咔咔分 |
| --- | ---: | --- | ---: |
| C | 0–49 | 普通有效相遇 | +3 |
| U | 50–64 | 有一点特点 | +5 |
| R | 65–79 | 有一项表现较突出 | +8 |
| SR | 80–91 | 至少两项分数 ≥ 70 | +13 |
| UR | 92–100 | 灵气 ≥ 85 且机灵 ≥ 80 | +21 |

判定顺序：先判断 UR，再判断 SR，再按咪咔区间判断 R / U / C。这样高魅力照片不能只靠一个指标直接进入 UR。

例子：

```text
94 / 91 / 93 → 咪咔 93 → UR
98 / 78 / 91 → 咪咔 89 → SR，不是 UR
72 / 69 / 68 → 咪咔 70 → R
```

## 8. 奖励规则

### 8.1 猫爪

猫爪是用户经验值名称，与相遇等级独立计算；累计猫爪对应的会员名称和成长阈值见 [用户成长会员等级规则 v0.1](./MEMBER_LEVEL_RULES_V0_1.md)：

```text
猫爪 = roundToNearest5(70 + 咪咔 × 0.6)
```

约为 `+70` 到 `+130`。例如咪咔 75，获得猫爪 `+115`。

### 8.2 咔咔分

咔咔分按相遇等级固定发放：`C +3`、`U +5`、`R +8`、`SR +13`、`UR +21`。

评分服务异常、评分证据不足或拍摄未通过时，不应按高等级预发奖励。

## 9. 与猫咪身份向量的关系

```text
猫咪身份向量：回答“是不是之前那一只猫”
相遇评分：回答“这一次照片呈现得有多特别”
```

身份向量、稳定花纹和脸部记号可以帮助归档同一只猫，但不能直接给相遇分加分；本次姿态、眼神和场景也不能修改猫咪身份向量。

## 10. 版本与历史记录

- 新结果使用 `scoreVersion = cat-score.v0.2`；
- 旧记录中的 `rarity / fate` 字段只作兼容读取，不作为新识别结果输出；
- 旧字段最接近的迁移关系为：旧 `rarity` → 新 `aura`，旧 `fate` → 新 `cleverness`，迁移时标记为 `legacy`；
- 评分规则或模型版本变化时，不覆盖原始分数，新增版本化结果；
- 上线前使用同猫/不同猫、不同视角和不同质量的真实样本校准分布，目标分布仍以 C 级为主，不做用户之间动态排名。

## 11. 本版确定项与后续待定项

### 已确定

1. 正式指标为魅力、机灵、灵气；
2. 三项等权；
3. 服务端根据证据子项计算最终分；
4. 图鉴稀有度不进入相遇评分；
5. 等级沿用 `C / U / R / SR / UR`；
6. 相遇评分与猫咪身份向量分离。

### 待校准

1. 图片质量和证据覆盖的最终门槛；
2. GLM 各子项的标注一致性；
3. 五档实际分布和奖励经济性；
4. 中文等级副标题是否继续使用“街角 / 偶见 / 稀遇 / 惊鸿 / 神隐”。

# 猫咪咔咔 — 软萌相机 UI 风格定义 v2.0

> 阶段：视觉方向定义 / 组件基线
>
> 本稿先定“看起来像什么、用起来是什么感觉”，不改小程序代码，也不替代玩法规则。
>
> 视觉参考：用户提供的软萌相机稿。参考图中的候选等级文案不作为最终规则；本稿使用已经确认的五级命名。

## 1. 方向一句话

**像一本贴在身边的猫咪小册子里，藏着一台轻轻一按就能记录相遇的相机。**

英文方向名：**Soft Camera / Gentle Cat Spotter**

关键词：

`轻`　`软`　`亲近`　`留白`　`小仪式感`

这次不走“旧纸张、档案馆、复杂任务面板”的路线。界面要先让用户看到猫、看到还能拍几次，然后自然地完成一次记录。

## 2. 五条设计原则

### 2.1 相机优先

首页的第一目的就是拍照。剩余罐罐放在顶部持续可见，主要按钮只保留一个：猫爪快门。

### 2.2 软萌但不吵

用大圆角、低饱和糖果色、轻阴影表达可爱；贴纸和星星只做气氛，不覆盖猫咪主体，也不把页面变成装饰墙。

### 2.3 真实照片，插画做引导

用户拍到的猫保持真实、清晰；插画只用于空状态、加载状态、识别中的提示，不用插画代替真实猫照片。

### 2.4 数值藏在结果里

拍摄时不堆等级、猫爪、咔咔分等信息；拍完后在揭示卡中一次说清楚奖励和卡片等级。

### 2.5 卡片稀有度与画面工艺分开

五级是遇见稀有程度；以后若使用 AR、SAR 等词，只描述插画/卡面工艺，不再新增一套容易混淆的等级。

## 3. 色彩系统

整体使用奶油白做大面积背景，珊瑚色承担主要动作，紫、绿、粉负责状态层次。颜色要“有颜色但不刺眼”。

| 角色 | 色值 | 使用位置 |
| --- | --- | --- |
| 奶油白 | `#FFF9F2` | 页面、卡片、底部操作区 |
| 温柔白 | `#FFFDF9` | 快门外圈、输入区域、照片边框 |
| 奶糖粉 | `#F2D7DE` | 选中态、柔和背景、轻提示 |
| 猫爪珊瑚 | `#EB7D6F` | 快门、主按钮、强调数字、结果标题 |
| 云朵紫 | `#D5CBE9` | 取景区、次级控件、空状态 |
| 薄荷绿 | `#B8D4C2` | 成功、已收集、柔和正向反馈 |
| 蜜糖黄 | `#F4DFA9` | R 级及奖励高光，少量使用 |
| 暖墨紫 | `#5D5260` | 标题、正文、图标 |
| 雾灰紫 | `#8F8190` | 辅助说明、时间、次级文字 |
| 线条淡紫 | `#E7DCE1` | 分隔线、边框、虚线取景框 |

### 颜色使用比例

- 70% 奶油白 / 温柔白：保持呼吸感；
- 20% 云朵紫、薄荷绿、奶糖粉：承载区域和状态；
- 10% 猫爪珊瑚、蜜糖黄：只给行动、数字和关键结果。

不使用大面积深棕、纯黑、荧光色，也不使用高对比的“游戏面板”配色。

## 4. 字体与文案

### 字体角色

- **标题**：`Songti SC` / `STSong` / 系统衬线字体。用于页面标题、猫咪名字、结果卡标题，带一点故事感。
- **界面正文**：`PingFang SC` / `Hiragino Sans GB` / 系统无衬线字体。用于按钮、状态和说明，确保小屏清晰。
- **英文识别**：全大写、字距拉开，例如 `CAT SPOTTER`、`CAT FOUND`；英文是气质标签，不承担关键信息。

### 文案语气

短、轻、像在和用户一起发现一只猫：

- 正在拍摄：`正在找猫` / `轻轻按下，收下这次相遇`
- 找到目标：`它在这里 · 保持一点距离`
- 处理中：`正在收下这次相遇`
- 今日用完：`今天的罐罐用完啦`
- 明日提示：`明天再来找猫`

避免：`开始任务`、`执行捕捉`、`战力`、`失败惩罚`、`剩余次数不足`。

### 建议字号（以小程序 rpx 另行换算）

| 层级 | 建议字号 | 字重 |
| --- | --- | --- |
| 页面标题 | 24–28 px | 500 |
| 猫咪/结果标题 | 22–26 px | 500 |
| 正文与按钮 | 15–17 px | 400–500 |
| 状态标签 | 12–14 px | 500 |
| 英文眉题 | 10–12 px | 500，字距 2–3 px |

## 5. 形状、边框与阴影

- 页面卡片：圆角 `24–32 px`；
- 状态胶囊：圆角 `999 px`；
- 快门按钮：圆形，外圈至少比按钮大一圈，形成软软的“按压靶心”；
- 普通边框：`1 px` 淡紫线；
- 相机取景框：白色 `2 px` 虚线，圆角 `20–24 px`；
- 阴影：`0 8px 24px rgba(93, 82, 96, 0.10)`，只用于层次，不做厚重投影；
- 装饰元素可轻微旋转 `-2° 至 2°`，功能控件不要倾斜。

所有可点击控件都应有足够的触摸面积；视觉上可以小，点击区域不能小。

## 6. 核心组件定义

### 6.1 今日罐罐胶囊

位置：相机页/首页顶部右侧，始终可见。

结构：小罐罐图标 + `今日罐罐 2/3`。数字用猫爪珊瑚突出，不能只靠颜色表达剩余量。

状态：

- `3/3`：三个罐罐都亮起，按钮可用；
- `2/3`、`1/3`：按拍摄任务提交即时减少；识别失败不返还，服务异常才返还；
- `0/3`：图标变为低饱和空罐，快门禁用，显示明日提示。

### 6.2 软萌取景区

背景为云朵紫 → 薄荷绿 → 奶糖粉的轻渐变，中央保留足够空间给真实猫咪。默认包含：

- 左上状态：`正在找猫`；
- 右上状态：`不打扰模式`，默认理解为不主动开闪光；
- 四角取景辅助线；
- 底部提示：`它在这里 · 保持一点距离`。

空状态可放一只简单的橘色猫咪插画；识别到猫后，对焦圈短暂使用珊瑚色，并出现一颗小爱心即可。

### 6.3 猫爪快门

这是全页唯一的一级动作：珊瑚色实心圆 + 温柔白外圈 + 猫爪图标。

交互反馈：按下缩小到 `96%`，白色闪一下，轻微震动；提交后立即锁定并扣除 1 个罐罐，避免重复提交。

按钮附近只说明一次：`会使用 1 个罐罐`。不要在快门旁边同时放任务、等级或奖励明细。

### 6.4 结果揭示卡

结果卡使用奶油白底，分为四层：

1. `CAT FOUND` 结果眉题；
2. 猫咪名字与实拍照片；
3. 等级短标签；
4. 本次奖励：`猫爪 +115`、`咔咔分 +8`。

其中“咔咔分”是可累计资源名称；`猫爪`作为经验名称使用。

结果揭示用轻微上浮、翻卡或渐显完成，不使用爆炸式粒子和长时间动画。

### 6.5 底部导航

保留三个明确入口：`找猫`、`图鉴`、`我的`。

当前页使用猫爪珊瑚作为 active 状态；未选中项使用暖墨紫与低饱和图标。导航是路标，不是第二个主视觉。

## 7. 三个页面的视觉分工

### 找猫 / 首页

核心问题：**我今天还能拍几次？**

第一屏只突出取景/拍照和 `今日罐罐`。不放大型任务看板，不放固定数量的图鉴进度，不把猫爪和咔咔分做成首页 dashboard。

### 图鉴 / Album

核心问题：**我遇见过哪些猫？**

照片卡片优先，等级使用统一短标签；未遇见的条目用柔和剪影或留白占位，不制造“缺了多少只”的焦虑感。重复拍摄进入同一猫咪的相遇记录。

### 我的 / My Meow

核心问题：**我的相遇留下了什么？**

展示猫爪等级、累计相遇、最近记录和偏好设置。这里才适合放个人成长信息；依然用轻量卡片，不做复杂数据后台。

## 8. 五级标签的视觉基线

代码先按 `C / U / R / SR / UR` 设计；中文等级标签暂不写死。下面是五套卡面视觉主题名，主题名不等于最终等级名称：

| 代码 | 视觉主题名 | 卡面短标签位置 | 色彩倾向 |
| --- | --- | --- | --- |
| C | 薄荷留影 | 左上代码 + 右上眉题 | 薄荷绿 + 苔藓绿 |
| U | 云朵探头 | 左上代码 + 右上眉题 | 云朵紫 + 灰紫 |
| R | 蜜糖闪现 | 左上代码 + 右上眉题 | 蜜糖黄 + 暖金 |
| SR | 珊瑚星轨 | 左上代码 + 右上眉题 | 珊瑚粉 + 猫爪珊瑚 |
| UR | 月光神隐 | 左上代码 + 右上眉题 | 夜幕紫 + 月光金 |

等级色只用于标签、边缘和少量高光；不把颜色做成“战力高低”，也不使用皇冠、火焰等竞技符号。具体卡面结构见 [相遇卡规则与五级卡面样式](./CARD_SYSTEM_V0_1.md)。

## 9. 动效与反馈节奏

| 时机 | 反馈 | 建议节奏 |
| --- | --- | --- |
| 罐罐减少 | 当前图标轻微缩放后回到原位 | 180–240 ms |
| 按下快门 | 缩小、白闪、轻震 | 120–180 ms |
| 识别中 | 对焦圈呼吸或小点循环 | 800–1200 ms，可关闭循环 |
| 卡片揭示 | 从下向上浮出，奖励依次出现 | 400–600 ms |
| 错误提示 | 页面内柔和提示卡 | 不用打断式弹窗 |

动效的目标是让用户感到“收下了一次相遇”，不是制造抽卡赌博感。

## 10. 明确不做

- 不做旧纸张、深棕色、手账贴满页面的档案馆视觉；
- 不在首页放多个任务卡、咔咔分看板或复杂进度条；
- 不把“固定 60 个猫咪条目”作为视觉前提，图鉴应支持动态增加；
- 不让等级标签像战斗稀有度或价格标记；
- 不让装饰图形遮挡真实猫咪；
- 不在本轮进入 WXML/WXSS/JS 实现。

## 11. 本轮交付边界

本稿确定的是：软萌相机方向、配色、字体、形状、快门、罐罐、结果卡和三页的视觉分工。

下一步再基于这套基线分别出：

1. 找猫首页 / 相机页完整 UI；
2. 图鉴页完整 UI；
3. 我的页面完整 UI；
4. 拍摄成功后的卡片揭示流程。
